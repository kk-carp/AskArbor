## 1. 依赖与默认顺序

```text
V1-T1 登录与用户 ──► V1-T2 空间成员授权收口
                         │
         ┌───────────────┼───────────────┬──────────────┐
         ▼               ▼               ▼              ▼
      V1-T3           V1-T5           V1-T6          V1-T4
   文档后台        学员工单       内部负责人         会话
         │               │               │              │
         └───────────────┴───────┬───────┴──────────────┘
                                 ▼
                            V1-T7 Compose 整包
```

**默认可并行（均依赖 T2 收口后）：** T3、T5、T6；T4 可与 T5/T6 并行，但建议在分流稳定后再接会话上下文。

**默认执行顺序：** T1/T2 收口 → T3 → T5 + T6 → T4 → T7。

## 3. 任务明细



### V1-T1 登录与用户（收口）

**目标：** 无游客问答；密码不明文；学员可绑定班主任；管理员能力可区分。

**当前状态：** 部分完成。

**已有交付：**

- `app/models.py`：`User`（含 `advisor_id`）
- `app/services/auth_service.py`、`app/routes/auth.py`
- `app/seed/demo_users.py`、`app/static/index.html` 登录
- `tests/integration/test_auth.py`

**差距动作：**

1. 种子或管理接口为 `student_demo` 绑定 `advisor_id`（可指向教学岗/班主任演示账号）。
2. `POST /documents` 改为需登录且仅管理员（或教学岗）可上传；未登录 401。
3. （可选最小）管理员创建用户接口；若本迭代不做，文档标明「仅种子账号」。
4. README 明确：默认 `SECRET_KEY`/`DEMO_PASSWORD` 仅本地演示。

**建议交付路径：**

- `app/routes/auth.py`、`app/services/auth_service.py`、`app/seed/demo_users.py`
- `app/routes/documents.py`（接入鉴权）
- `tests/integration/test_auth.py` 增补上传鉴权与班主任字段用例

**验证：**

```powershell
pytest tests/integration/test_auth.py -q
# 未登录：
curl.exe -X POST "http://127.0.0.1:8000/ask" -H "Content-Type: application/json" -d "{\"question\":\"hi\"}"
# 期望 401
```

**通过标准：**

- 未登录 `/ask` → 401；密码哈希存储。
- 学员用户存在可用的班主任绑定（字段非空，可供 T5 使用）。
- 未登录上传 → 401（收口后）。

**回归风险：** 破坏现有演示页登录 Cookie 流程；需同步静态页。

### V1-T2 空间成员授权收口

**目标：** 允许空间只来自 `space_members`；客户端伪造 `role`/`space_ids` 无效；教学岗两空间可检。

**当前状态：** 核心已完成，需收口。

**已有交付：**

- `app/domain/membership.py`、`app/models.py`：`SpaceMember`
- `app/routes/ask.py` → `load_auth_context` → `allowed_spaces`
- `AskRequest` 仅 `question`（额外字段忽略）
- `tests/unit/test_membership.py`、`tests/integration/test_auth.py` 伪造空间用例

**差距动作：**

1. 确认业务代码与 README/`docs` 不再教人用请求 `role` 问答。
2. 保留或删除 `app/domain/roles_compat.py`：仅作「角色→应写入成员」种子辅助则改名说明；禁止问答路径调用。
3. 补充回归：学员成员仅 `student` 时问公司制度 → `hit=false` 且无 company 来源。

**验证：**

```powershell
pytest tests/unit/test_membership.py tests/integration/test_auth.py -q
```

**通过标准：**

- `/ask` 计算空间不读请求体 `role`/`space_ids`。
- 学员检不到 `company`；教学岗可检两空间。
- 检索 SQL 仍含 `chunks.space_id = ANY(...)` 与 `documents.status = 'ready'`。

**回归风险：** 误删种子里的成员写入导致全员空空间。

### V1-T3 文档后台（状态 / 失败 / 下线）

**目标：** 文档状态与失败原因可见；下线后不可检索。

**当前状态：** 部分完成。

**已有交付：**

- `DocumentStatus`：`processing` / `ready` / `failed` + `error`
- `app/services/ingest_service.py`、`POST /documents`
- `app/infra/retrieve.py` 仅 `ready`

**差距动作：**

1. 扩展状态 `offline`（枚举 + 迁移/启动建表策略与现有一致：可 `create_all` + 应用层约束）。
2. `GET /documents`：返回 id、title、space_id、status、error、chunk_count。
3. `POST /documents/{id}/offline`（或 PATCH）：仅管理员；下线后检索不到。
4. 管理页最小展示（可扩 `static/index.html` 或独立管理区块）。
5. 上传鉴权依赖 T1 收口。

**建议交付路径：**

- `app/models.py`、`app/schemas.py`
- `app/routes/documents.py`、`app/services/ingest_service.py`（或 `document_admin_service.py`）
- `app/infra/retrieve.py`（显式排除 `offline`/`failed`）
- `tests/unit` + `tests/integration` 文档管理用例

**验证：**

```powershell
# 上传后列表可见 ready；人为下线后再 ask 相关问题应 miss
pytest tests -k "document or offline or ingest" -q
```

**通过标准：**

- `failed`/`offline` 不出现在检索。
- 列表能看到失败原因（`error`）。
- 非管理员不可下线/上传（与 T1 策略一致）。

**回归风险：** 改 status 枚举导致旧数据不兼容；需幂等处理。

### V1-T4 会话（同一会话追问）

**目标：** 支持 `conversation_id` 追问；对话不自动入库。

**当前状态：** 已完成。

**已有交付：**

- `conversations` / `messages` 表（归属 `user_id`）；消息不写入 `documents`/`chunks`
- `POST /ask` 可选 `conversation_id`；响应返回 `conversation_id`；无则新建
- 生成阶段注入最近 3 轮（`conversation_history_turns`）；DeepSeek 多轮 `messages`，本轮片段在最后一条并强调「仍以本轮片段为准」
- 检索仍只按本轮问题 + `allowed_spaces`；来源仍只来自本轮召回
- 命中/未命中落库用户+助手消息；502/503 整次回滚不落库
- `GET /conversations`、`GET /conversations/{id}/messages`
- Streamlit 问答页支持选会话 / 新会话 / 追问
- 单测与集成：`tests/unit/test_conversation_service.py`、`test_qa_conversation.py`、`test_generate.py`、`tests/integration/test_conversations.py`

**差距动作：**

1. ~~表：~~`conversations`~~、~~`messages`~~（归属 user_id）。~~
2. `/ask` ~~可选~~ `conversation_id`~~；无则创建新会话。~~
3. ~~生成阶段可带最近 N 轮用户/助手文本，但检索仍只在~~ `allowed_spaces`~~；来源仍只来自本轮召回。~~
4. ~~禁止把消息写入~~ `documents`~~/~~`chunks`~~。~~

**建议交付路径：**

- `app/models.py`、`app/services/conversation_service.py`
- `app/services/qa_service.py`、`app/routes/ask.py`、`app/routes/conversations.py`、`app/schemas.py`
- `tests/unit/test_qa_service.py`、集成会话用例

**验证：**

```powershell
# 登录后连续两次 /ask 同一 conversation_id，messages 表有记录且无新 documents
pytest tests -k "conversation or ask" -q
```

**通过标准：**

- 同会话可追问；消息落库但不进入向量索引。
- 未命中语义不变；502/503 不写入用户/助手消息（整次回滚）。

**回归风险：** 历史对话导致模型忽略片段；已用 Prompt 约束「仍以本轮片段为准」。

**实现约定（落库）：**


| 场景          | 用户消息   | 助手消息   |
| ----------- | ------ | ------ |
| `hit=true`  | 写入     | 写入答案   |
| `hit=false` | 写入     | 写入固定拒答 |
| 502 / 503   | 不写（回滚） | 不写（回滚） |

### V1-T5 学员工单

**目标：** 学员未命中（或显式转人工）建工单；默认处理人=班主任；502 不建单。

**当前状态：** 已完成。

**已有交付：**

- `tickets` 表：`question` / `student_id` / `assignee_id` / `status(open|replied)` / `reply` / 可选 `conversation_id`
- 学员 `hit=false` 自动建单；`POST /tickets` 显式转人工；处理人一律服务端取 `advisor_id`
- 无班主任 → 400「学员未绑定班主任，无法建工单」
- `/ask` 响应返回 `ticket_id`；502/503 不建单；员工未命中不建单
- `GET /tickets`：学员看自己的；处理人看指派；教学岗/admin 看全部
- `POST /tickets/{id}/reply`：处理人（或教学岗/admin）回复；回复不入库
- Streamlit「工单」页 + 问答页展示自动建单 `ticket_id`
- 测试：`tests/unit/test_ticket_service.py`、`test_qa_tickets.py`、`tests/integration/test_tickets.py`

**差距动作：**

1. ~~表 `tickets`。~~
2. ~~学员未命中自动建单 + `POST /tickets`。~~
3. ~~班主任列表与回复接口；回复不入库。~~
4. ~~单元测试：mock 未命中建单；mock 502 不建单。~~

**建议交付路径：**

- `app/models.py`、`app/services/ticket_service.py`、`app/routes/tickets.py`
- `app/services/qa_service.py` 或路由层分流钩子
- `tests/unit/test_ticket_service.py`、`tests/integration/test_tickets.py`

**验证：**

```powershell
pytest tests -k "ticket" -q
```

**通过标准：**

- 仅学员建单；处理人默认 `advisor_id`。
- 502/503 不建单。
- 员工未命中不建学员工单。

**回归风险：** 与 T6 分流条件写乱；必须按角色分支清晰。

### V1-T6 内部负责人联系方式

**目标：** 员工未命中展示负责人或「未配置」；禁止编造。

**当前状态：** 已完成。

**已有交付：**

- `app/models.py`：`TopicOwner`（`topic_key` / 名称 / 关键词 / 姓名 / 联系方式）
- 种子样例：请假、报销、IT、考勤（`example.local` 演示联系方式；已有记录不覆盖）
- 员工（含教学岗）`hit=false` 时按问题关键词匹配，返回 `owner`；无匹配 `configured=false`
- 学员路径 `owner=null`，不泄露内部联系人
- `GET/PUT /topic_owners`：仅教学岗/管理员
- 拒答文案仍为固定 `MISS_ANSWER`，联系方式不经 DeepSeek
- Streamlit「主题负责人」页 + 问答页展示 `owner`
- 测试：`tests/unit/test_topic_owner_service.py`、`test_qa_owners.py`、`tests/integration/test_topic_owners.py`

**差距动作：**

1. ~~表 `topic_owners`。~~
2. ~~未命中且员工时查询匹配；无匹配返回明确「未配置」。~~
3. ~~种子样例主题 + 管理接口。~~
4. ~~响应字段与拒答文案分离。~~

**建议交付路径：**

- `app/models.py`、`app/services/topic_owner_service.py`、`app/routes/...`
- `app/schemas.py` 扩展 Ask 响应或并列字段
- `tests/unit/test_topic_owner_service.py`

**验证：**

```powershell
pytest tests -k "topic_owner or owner" -q
```

**通过标准：**

- 有配置则返回库中真实联系方式；无配置不编造。
- 学员路径不返回内部负责人（避免泄露）。

**回归风险：** 把负责人匹配误接到 DeepSeek Prompt。

## 4. 跨任务验收清单（V1 产品关卡）

与 `docs/V1需求分析.md` 第 8 节对齐，建议在 T5/T6/T3/T7 完成后做一轮总验收：

1. 登录隔离 + 伪造空间无效（T1/T2）。
2. 文档下线不可检（T3）。
3. 学员未命中建单；员工未命中负责人或未配置（T5/T6）。
4. 会话追问不入库（T4）。
5. Compose 整包可起（T7）。
6. SQL 空间过滤回归：`pytest tests/unit/test_retrieve.py -q`。

## 5. 明确不做（任一 V1 任务均禁止）
