# 混合检索与重排设计（实现前约定）

> 状态：已拍板并实现中。默认 **hybrid + rerank 双开**；模型 `BAAI/bge-reranker-v2-m3`；`rerank_min_score=0.0`。  
> 目标：在保持空间隔离、ready-only、拒答语义不变的前提下，把单路 dense 检索升级为「多路召回 → 融合 → 重排 → 阈值」。

---

## 1. 背景与目标

### 1.1 现状

```
问题 →（可选岗位 boost）→ BGE-M3 encode_query
     → search_chunks（pgvector <=> cosine，top_k=5）
     → max(score) < 0.3 则拒答
     → 否则 DeepSeek + DB 来源
```

主路径：`qa_service._retrieve` → `embed.encode_query` → `retrieve.search_chunks`。  
进阶资料课内检索同样调用 `run_retrieval` / `search_chunks`。

### 1.2 要解决的问题


| 现象                 | 原因（约）                 |
| ------------------ | --------------------- |
| 专有名词 / 路径 / 报错码召回弱 | 纯语义对精确词不敏感            |
| top_k 小且无重排        | 相关片段排在第 6+ 被截断，或噪声排在前 |
| 假命中                | 余弦分数与「是否够依据」不完全对齐     |




### 1.3 目标（本专项）

1. **混合召回**：dense + 关键词（词法）两路，SQL 内仍强制 `space_id` + `documents.status='ready'`。
2. **融合**：RRF（Reciprocal Rank Fusion），不引入 Elasticsearch。
3. **重排**：对融合后的候选做 cross-encoder 精排，再截断为最终 `top_k`。
4. **开关可回退**：配置关闭混合/重排时行为与现网一致（仅 dense + 原阈值）。
5. **不改**：SkillHub、Agent、流式、切片策略大改、分类型独立索引。



### 1.4 非目标

- 不上 ES/OpenSearch、不上 Celery 异步索引。
- 不用 BGE-M3 sparse / ColBERT（模型与存储成本更高，本轮不做）。
- 不改「来源必须来自 DB 召回」「未过阈值不调 DeepSeek」。
- 不让客户端传 `space_ids` / 检索参数覆盖服务端策略。

## 2. 目标流水线

```
question
  → retrieval_query_for_question (+ boost_retrieval_query)
  → ┌─ dense: encode_query → search_dense(candidate_k)
    └─ lexical: search_lexical(query_text, candidate_k)
  → RRF 融合 → 去重（chunk 主键）→ 取 fusion_top_n
  → rerank(query, candidates) → 取 retrieve_top_k
  → 阈值门控（见 §5）→ generate / miss
```

对外仍只暴露现有 `/ask`、`/ocr`；检索实现细节不出 API。

## 3. 技术选型（本轮拍板）



### 3.1 词法召回：PostgreSQL 全文检索（tsvector）


| 项             | 选择                                                                                                                 |
| ------------- | ------------------------------------------------------------------------------------------------------------------ |
| 存储            | `chunks.content_tsv tsvector`（入库时写入）                                                                               |
| 索引            | `GIN(content_tsv)`                                                                                                 |
| 查询            | `plainto_tsquery('simple', :q)` + `ts_rank_cd` 排序                                                                  |
| 中文            | **入库前用 jieba 分词**，以空格拼成 `search_text`，再 `to_tsvector('simple', search_text)`；查询侧对用户问题同样 jieba 后再 `plainto_tsquery` |
| 为何不用 zhparser | 依赖 PG 扩展与运维镜像，本地/演示环境难统一                                                                                           |
| 为何不用纯 pg_trgm | 对中文长文噪声大；与精确词召回可叠加，但本轮先做 tsvector 一路                                                                               |


代码路径与文件名/报错串：jieba 对英文、路径、数字基本原样保留，可覆盖「精确词」场景的大部分需求。

### 3.2 融合：RRF


\mathrm{score}*{RRF}(d)=\sum*{r\in\mathrm{dense},\mathrm{lexical}}\frac{1}{k+rank_r(d)}


- 默认 `rrf_k=60`（可配置）。
- 某路未命中该 chunk 时该项为 0。
- 融合分只用于排序，**不直接**与现有 `retrieve_min_score=0.3` 比（量纲不同）。



### 3.3 重排：BGE Reranker（进程内加载一次）


| 项    | 选择                                                              |
| ---- | --------------------------------------------------------------- |
| 模型   | `BAAI/bge-reranker-v2-m3`（与 BGE-M3 同系列，中英均可）                    |
| 加载   | 与 embed 相同：API 启动时加载一次；`sentence-transformers` 的 `CrossEncoder` |
| 输入   | `(query_text, chunk.content)`                                   |
| 输出   | 相关性分数（logit/归一化后均可，见 §5）                                        |
| 候选规模 | 融合后取 `rerank_candidates`（默认 20）送入重排，再取 `retrieve_top_k`（默认 5）   |


备选（不默认）：若本机显存/内存不够，可用更小的 `BAAI/bge-reranker-base`，仅改配置项。

### 3.4 明确不做

- LangChain / LlamaIndex 编排。
- 远程 Rerank HTTP 服务（多一跳运维）。
- 按文档类型拆多套索引（可后续专项）。

## 5. 分数与拒答语义



### 5.1 问题

- dense：`1 - cosine_distance` ∈ 约 0,1，现网阈值 `0.3`。
- lexical：`ts_rank_cd` 量纲不同。
- RRF：秩融合分，通常很小。
- rerank：cross-encoder 原始分多为实数 logit，与 0.3 **不可直接比**。



### 5.2 约定（实现必须遵守）

1. **最终门控分数** = 重排后的分数（开启 rerank 时）；关闭 rerank 时回退为 **dense 余弦相似度**（与现网一致）。关闭混合但开启 rerank 时：仅对 dense 候选重排，门控仍用重排分。
2. 新增配置 `rerank_min_score`（默认建议先 **0.0** 或按小样本标定后再写死），**仅当** `retrieve_use_rerank=true` **时生效**。
3. 开启重排时：**不再**用 `retrieve_min_score` 与 rerank 分比较；避免量纲混用。关闭重排时继续用 `retrieve_min_score`。
4. Miss 条件不变：候选空，或最终 top 分低于对应阈值 → 固定拒答、不调 DeepSeek、`error_type=miss`。
5. `RetrievedChunk.score` 对外/来源展示：写最终用于排序与门控的分数（重排开启则为 rerank 分，并在实现注释中标明）。



### 5.3 进阶资料推荐

与问答共用检索函数；课内工具走同一套「最终分 + 对应阈值」，避免分叉。

## 6. 配置项（`backend/config.py` / `.env`）


| 配置                     | 默认                        | 含义                               |
| ---------------------- | ------------------------- | -------------------------------- |
| `retrieve_top_k`       | `5`                       | 最终送给生成的条数（保持）                    |
| `retrieve_min_score`   | `0.3`                     | **仅 dense-only / 关 rerank** 时的门控 |
| `retrieve_use_hybrid`  | `true`                    | 是否启用词法路 + RRF                    |
| `retrieve_use_rerank`  | `true`                    | 是否启用重排                           |
| `retrieve_candidate_k` | `20`                      | 每路召回条数（dense / lexical 各自 LIMIT） |
| `retrieve_rrf_k`       | `60`                      | RRF 常数                           |
| `rerank_model`         | `BAAI/bge-reranker-v2-m3` | 重排模型                             |
| `rerank_candidates`    | `20`                      | 送入重排的融合候选上限                      |
| `rerank_min_score`     | `0.0`                     | 开 rerank 时的门控（已拍板初值；可按分布上调）   |


推荐本地调试组合：

- 对照基线：`retrieve_use_hybrid=false` + `retrieve_use_rerank=false`
- 只混合：`hybrid=true` + `rerank=false`
- 全开：两者 `true`

## 7. Schema 与 backfill



### 7.1 DDL（在 `db.init_db` 中幂等执行）

```sql
ALTER TABLE chunks ADD COLUMN IF NOT EXISTS content_tsv tsvector;
CREATE INDEX IF NOT EXISTS ix_chunks_content_tsv ON chunks USING GIN (content_tsv);
```



### 7.2 写入时机

- 新入库：`ingest_service` / `code_ingest_service` 在 insert chunk 时：
  - `search_text = jieba_cut(content)`
  - `content_tsv = to_tsvector('simple', search_text)`（SQL 侧 `to_tsvector` 或应用侧生成后绑定）
- 已有数据：`init_db` 或一次性脚本：对 `content_tsv IS NULL` 的行按 `content` 分词回填。失败文档不参与检索，但仍可回填，避免日后恢复 ready 时缺索引。



### 7.3 空间过滤（硬约束）

`search_lexical` 与 `search_dense` 的 `WHERE` **必须**包含：

```sql
chunks.space_id = ANY(...)
AND documents.status = 'ready'
```

禁止「先全表再在 Python 滤空间」。

## 8. 核心接口形状（实现时对齐）

```python
# retrieve.py
def search_dense(query_vector, allowed_spaces, top_k) -> list[RetrievedChunk]: ...
def search_lexical(query_text, allowed_spaces, top_k) -> list[RetrievedChunk]: ...
def fuse_rrf(rank_lists: list[list[RetrievedChunk]], rrf_k: int) -> list[RetrievedChunk]: ...
def hybrid_search(
    query_text: str,
    query_vector: list[float],
    allowed_spaces: list[str],
    *,
    candidate_k: int,
    rrf_k: int,
    use_lexical: bool,
) -> list[RetrievedChunk]: ...

# 兼容：search_chunks(...) 内部调用 hybrid_search 或 search_dense

# rerank.py
def rerank(query: str, chunks: list[RetrievedChunk], top_k: int) -> list[RetrievedChunk]: ...
```

`qa_service._retrieve` 伪代码：

```python
query_text = boost_retrieval_query(retrieval_query_for_question(...), position_key)
query_vector = encode_query(query_text)
candidates = hybrid_search(...)  # 或 dense-only
if settings.retrieve_use_rerank:
    retrieved = rerank(query_text, candidates[:rerank_candidates], retrieve_top_k)
    gate = settings.rerank_min_score
else:
    retrieved = candidates[:retrieve_top_k]
    # 关 hybrid 时 candidates 已是 dense；开 hybrid 关 rerank 时用 dense 分门控需额外策略：
    # 约定：关 rerank 时最终列表的 score 取该 chunk 的 dense 分（融合阶段保留 dense_score 字段）
    gate = settings.retrieve_min_score
if not retrieved or max(c.score for c in retrieved) < gate:
    return []
return retrieved
```

**关 rerank 时的 score**：`RetrievedChunk` 可扩展可选 `dense_score`；融合排序用 RRF，门控与展示在关 rerank 时写回 `dense_score`（无 dense 分的纯词法命中：可门控失败或给 0，避免假命中——**约定纯词法-only 命中在关 rerank 时 score=0，除非也在 dense 列表中**）。

## 9. 实现顺序（建议 PR 切分）

1. **Schema + lexical 写入 +** `search_lexical` **+ 单测**（仍不切换主路径）。
2. **RRF +** `hybrid_search` **+ 配置开关**；默认可先 `false`，测通后改 `true`。
3. `rerank` **模块 + 启动加载 +** `_retrieve` **接线**；标定 `rerank_min_score`。
4. **进阶资料对齐 + 文档同步 + 小样本人工评测**（专有词、代码路径、政策类问句、应拒答问句）。

## 10. 风险与约束


| 风险                  | 缓解                          |
| ------------------- | --------------------------- |
| 多加载一个 rerank 模型，内存↑ | 配置可关；可用更小模型名                |
| jieba 分词与业务词不一致     | 后续可加用户词典；本轮不加复杂词典文件         |
| 阈值乱调导致拒答率骤变         | 开关回退；先关 rerank 用 dense 阈值对照 |
| backfill 阻塞启动       | 大批量时后台分批；或独立脚本，启动只建列建索引     |
| 与课程文档「MVP 不做混合」表述冲突 | 落地时改 `技术选型.md` / 架构文档，标明已升级 |

## 11. 验收标准

1. `student` / `employee` / `teaching` 空间隔离用例仍过（SQL 含 `space_id`，无 Python 事后滤全量）。
2. `failed` 文档仍不可召回。
3. 混合+重排开启时：至少 1 组「专有名词/路径」问句召回优于纯 dense（人工或脚本对比）。
4. 低于阈值仍固定拒答且不调用 DeepSeek。
5. `retrieve_use_hybrid=false` 且 `retrieve_use_rerank=false` 时，行为与改前一致（含 `test_qa_service` / `test_retrieve`）。
6. 来源列表仍由召回记录生成，模型不改来源。

---



## 12. 已确认决策

1. 默认 **双开** hybrid + rerank。
2. Rerank 模型：`BAAI/bge-reranker-v2-m3`。
3. `rerank_min_score` 初值 **`0.0`**（几乎只靠有候选 + top_k；后续按分数分布上调）。
