## 1. 原则（继承产品硬约束）

与 `docs/需求分析.md` §8.3、V2-A/V2-B 硬约束一致，上课实现也不得破坏：

1. 一套 RAG 内核、两个空间；不为某一课另起向量库或第二套 FastAPI。
2. 空间过滤在检索 SQL 的 `WHERE` 中；客户端与工具入参不得决定 `space_ids`。
3. `/ask` 未命中或低于阈值 **不调用** DeepSeek；来源只来自召回。不为了教 Agent 而在拒答前先让模型选工具。
4. 系统故障（502/503）、知识库未命中（`hit=false`）、工具失败（OCR / Skill / 搜索）三种语义分开。
5. 不为教学预建空的 `backend/agents/`；第一个可调用工具落地时再加文件。
6. 禁止任意 Shell、任意出网、代码执行沙箱（基线已删除 A2）。
7. 对话与 Skill 草稿不得自动入库。
8. 新依赖先改 `docs/技术选型.md` 再改 `requirements.txt`。

**进阶资料 vs 问答内工具：** 课外搜索走进阶资料推荐（`/advanced-resources`），不要改成「每轮 `/ask` 由模型决定是否搜索」。公司 Skill / 第 30 课工具演示**不占用本仓库 V2-B 入职验收**（见专项延后说明）。

## 3. 已可上课、不必另起功能的部分



### 3.1 第 28 课 RAG（产品主体）

对应 `docs/需求分析.md` §4、§11 MVP/V1/V2 学伴「代码可问到来源」。


| 讲点           | 代码入口                                                             |
| ------------ | ---------------------------------------------------------------- |
| 解析 / 切片 / 向量 | `backend/infra/parsers.py`、`chunker.py`、`embed.py`               |
| SQL 内空间隔离    | `backend/infra/retrieve.py`（`space_id = ANY` + `status='ready'`） |
| 阈值拒答、不调 LLM  | `backend/services/qa_service.py`                                 |
| 来源不由模型编造     | `SourceItem` 来自召回；命中代码切片带 `path`                                 |
| 双场景同一内核      | `student` / `company`；教学岗 `/ask` 两空间，插件再裁剪                       |


课上作业建议：改阈值或去掉 `WHERE` 空间条件，用现有隔离测试证明幻觉/越权会出现；**不要把去掉隔离的代码合入主分支。**

### 3.2 第 29 课 工作流与约束（产品已是手写编排）

对应未命中分流、错误语义、白名单出网。

```text
登录 → allowed_spaces
  → /ask：检索 → 低于阈值则拒答（学员工单 / 员工负责人）且不调 DeepSeek
           命中才 complete_chat
  → /advanced-resources：会话历史 → 归纳薄弱点 → 相关性闭环检索 + 成文
  → （产品延后）/skills/{name}/run：不作为本仓库 V2-B 必做
```

课上强调：**可靠性来自代码状态机，不是来自模型自觉。** 搜索失败、OCR 失败都不得写成 `hit=false`。

## 4. 按课补充实现（挂在现有需求上）

下列编号 **C26–C32** 只用于教学清单；产品任务号用 A5、B1/B2（入职）。Skill 不再占用 B3～B5。

### C26 提示词与输出控制（补强，不改 `/ask` 合同）

**已有：** `generate.py` 的 system/user 约束；薄弱点归纳要求 JSON 字符串数组（最多 3 项、无 URL）。`parse_topic_schema` 校验失败则再调 1 次；仍失败或上游错误则降级为近期问句截断，不 502、不成未命中。URL / 事务项在校验通过后丢弃，不触发重试。

**明确不做：** 在 `/ask` 上对答案做 JSON mode 以致前端无法展示自然语言；引入 LangChain 输出解析器。

**对应需求：** 幻觉控制（§4 拒答与来源）+ 进阶资料「禁止编造 URL」。

---



### C27 评估与成本（补强评测脚本）

**已有：** `scripts/run_phase1_eval.py`（命中率、拒答率、来源准确率、隔离通过率、延迟、token）；`docs/samples/eval/phase1_minimal_eval_set.jsonl`；`docs/评估与安全作业.md`。

**补充（已落地）：**

1. live 模式记录每条：墙钟延迟、`llm_called`、prompt/completion token（DeepSeek `usage`）。拒答应为 0 生成 token。
2. 汇总：平均 / P95 延迟、命中路径 vs 拒答路径 token 差。
3. `isolation` 类：学员问内部制度，来源不得含 `company`。
4. `/ask` 响应带 `llm_called` / `prompt_tokens` / `completion_tokens`；问答页不展示。

**明确不做：** 为评测引入第二套 RAG；在 CI 强制打真实 DeepSeek（保持 mock/oracle 可跑）；越狱产品拦截。

**对应需求：** §10 时效与正确性；§13 第九章观测（答疑解决率可后续接 V2-C1 日志）。

---



### C30 Agent 与工具调用（公司 Skill — 产品延后）

**现状：** 产品侧 V2-B **本阶段不做** Skill（见 `docs/V2-B需求分析.md`）。本节仅保留教学对照；实现请放 `experiments/` 或未来 Skill 专项，**不要**再把主仓库验收绑到 V2-B3～B5。

**若做实验演示，可参考的边界（非本仓库 V2-B 必做）：**


| 能力         | 示意接口                                    | 教学对应                                  |
| ---------- | --------------------------------------- | ------------------------------------- |
| 注册表 / 规划边界 | `GET /skills`、`POST /skills/{name}/run` | 只能点名已注册工具                             |
| 文章草稿       | `article_generate`                      | 检索 `company` + `complete_chat`；不入库   |
| 论文元数据      | `arxiv_fetch`                           | 只打 arXiv 白名单主机                         |


**课上对比：** 服务端规划（代码选工具）vs 模型在白名单内选名；仍禁止每轮 `/ask` 自动调工具、禁止 LangChain AgentExecutor、禁止客户端任意 URL。

**明确不做（与产品一致）：** 空 `agents/`；用工具结果冒充 `documents` 来源；把未完成的 Skill 算进 V2-B 入职验收。

---



### C31 多模态（视觉进产品，语音进实验）

**视觉（产品 = V2-A5）：**

- `POST /ocr` 或 `/ask` 支持图片 → OCR 文本 → 既有 `/ask`。
- `ocr_failed` ≠ `hit=false`，不建学员工单。
- 引擎先写入选型（建议 PaddleOCR）再加依赖。
- 学伴空间裁剪仍只有 `student`。

**语音（教学补充，不进基线 V2）：**

- 单独脚本或 `experiments/asr/`：音频 → 文本，再手工/脚本调用 `/ask`。
- **不**把 ASR 接到检索 SQL，**不**为语音新建空间。
- 失败语义与 OCR 相同：识别失败不是知识库未命中。

**明确不做：** 用多模态 LLM 直接看图答题而绕过 OCR+RAG（会破坏来源可核对）；摄像头/实时语音助手。

---



### C32 LoRA 微调（仅实验，对照「何时不该微调」）

基线选型是 **API 调用 DeepSeek + 进程内 BGE-M3**。微调主模型会破坏可演示的隔离 RAG，且无产品需求。

**实验约定：**


| 项          | 约定                                                                    |
| ---------- | --------------------------------------------------------------------- |
| 目录         | `experiments/lora/`（或课程指定路径），**不**导入 `backend/infra/embed.py` 的生产加载逻辑 |
| 数据         | 虚构、可公开的小样本（问答对或分类），禁止用真实内部 `company` 语料外带                             |
| 目标         | 演示 LoRA 能改风格/术语；对比同一问题：微调模型 vs 本系统 RAG 拒答/带来源                         |
| 结论（课上必须落到） | 制度/代码事实用检索；风格或固定口吻才考虑微调                                               |


**明确不做：** 用 LoRA 替换线上 `deepseek-chat` 或 BGE-M3；把 adapter 打进 Compose 默认 API 镜像。
