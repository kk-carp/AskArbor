# 进阶资料推荐设计（档位 B）

> 状态：**已实现**（白名单工具 + 相关性改写 + **推荐文章** + **SSE 实时轨迹**）。  
> 产品名：**进阶资料推荐**。  
> 定位：学伴场景下的**旁路小 Agent**（白名单工具 + 多步），与 `/ask` 拒答链、`GET /learning-path` 一键结果**并存**。  
> 编排：**自研**，**不使用** LangGraph / LangChain / LlamaIndex。

---

## 1. 背景与目标

### 1.1 为什么做

学习路径已能「一键」给出薄弱点 + 课内 + 课外列表，但第 30 课需要可讲解的 **Agent 形态**：工具注册表、点名执行、有限步进。进阶资料推荐把现有积木收成白名单工具，方便教学与产品进阶入口，**不重做检索内核**。

现网一键推荐常夹带**无关资料**（多薄弱点糊成一句 query、无相关性判断）。本能力默认带 **检索 → LLM 判定 → 改写搜索词再搜** 闭环。

### 1.2 目标

1. 提供独立 API：列出工具、单次执行、可选多步计划。
2. 工具只复用现有能力：薄弱点归纳、课内 `run_retrieval`、课外 `search_open_resources`；可选 OCR 识文。
3. **相关性闭环**：检索后由 LLM 判断命中是否贴合薄弱点；不相关则改写搜索词再搜，或丢掉无关条目；禁止把明显跑题的结果交给用户。
4. 默认知识空间仅 `student`（与 V2-A 学伴一致）；禁止客户端传 `space_ids`。
5. 工具失败 ≠ 知识库未命中；**不建学员工单**。
6. **不改** `/ask` 的阈值拒答与来源语义。

### 1.3 非目标

- 不接 SkillHub / 公司 Skill。
- 不用 LangGraph 或其他 Agent 框架。
- 不把 Agent 塞进每轮 `/ask`。
- 不做代码沙箱、代写作业、自动入库。
- 不替代 `GET /learning-path`（一键推荐仍保留；相关闭环可日后回灌）。

## 4. 白名单工具（第一期）

| tool | 包装 | 入参（示意） | 出参要点 |
| --- | --- | --- | --- |
| `summarize_weak_points` | 近期提问 → 薄弱点 | 可选 `limit` | `weak_points[]`；无 URL |
| `search_course` | `run_retrieval`，仅 `student` | `query` | 课内**候选**（title/path/snippet/score）；未过滤 |
| `search_external` | `search_open_resources` | `queries[]` | 课外**候选**；失败 `search_*` |
| `judge_relevance` | DeepSeek 判定去留 + 是否改写 query | `topic`、`channel`、`candidates`、`query` | 见 §4.2；**不得发明** document_id/URL |
| `ocr_transcribe`（可选） | OCR 识文 | 图片 | `text`；失败 `ocr_failed` |

**不做：** `ask_kb`、`create_ticket`、任意出网抓页。

硬约束：忽略客户端 `space_ids`；来源 id/URL 只出自检索工具；`judge_relevance` 只能筛选或提出新 `query`。

### 4.1 现网学习路径为何容易跑题

```text
薄弱点列表 → 拼成一句 query → 检索一次 → 原样推荐
薄弱点列表 → 直接课外搜索 → 原样推荐
```

多点糊成一串、无相关性判断、无改写 → 召回噪声直接露出。

进阶资料推荐改为：**按薄弱点逐个检索 → 判定 → 有限次改写**。

### 4.2 `judge_relevance` 约定

LLM 只输出 JSON：

```json
{
  "keep_ids": ["必须来自本轮候选的 id 或 url"],
  "drop_ids": ["..."],
  "need_refine": true,
  "refined_query": "更具体的搜索词，仅 need_refine 时",
  "reason": "一句话，可进审计"
}
```

服务端校验：

1. `keep_ids` / `drop_ids` ⊆ 本轮候选；多出的丢弃。
2. `need_refine=true` 时 `refined_query` 非空、无 URL、≤80 字；否则当作不改写。
3. **默认策略**：`keep_ids` ≥ 1 → 采用 keep，**本 topic×channel 不再 refine**；仅 keep 为空才允许 refine 再搜。
4. 每 topic×channel 最多 refine `advanced_resources_max_refine` 次（默认 **1**）。
5. 判定失败（上游错误 / JSON 无效）：降级为「保留 score 最高的前 K 条」（K 可配，默认 2），并打审计；**不**无限重试。

候选送给 LLM 时只传摘要字段（title、path、snippet、score），控制 token。

## 5. API 契约（草案）

### 5.1 `GET /advanced-resources/tools`

返回白名单元数据（含 `judge_relevance` 说明）。

### 5.2 `POST /advanced-resources/run`

单工具执行；未知工具 → 400/422；`ok=false` 带 `error_type`，不建单、不写 `hit=false`。

### 5.3 `POST /advanced-resources/plan`

**默认规则路由**（含相关性闭环）：

```text
1. summarize_weak_points（若尚无 topic）
2. 对每个 topic（最多 N 个，默认 3）：
     a. search_course(query=topic)
     b. judge_relevance(channel=course, ...)
     c. 若 keep 空且 need_refine 且未超 max_refine
          → search_course(refined_query) → 再 judge（只筛 keep，不再二次 refine 除非仍空且额度未用尽）
     d. search_external(queries=[topic])
     e. judge_relevance(channel=external, ...) 同样可 refine 一次
3. 汇总 keep 后的 course / external（去重）
```

`max_steps` 按「工具调用次数」计数（含 judge、refine 后的第二次 search）。建议默认调高到 **12**（约 3 个 topic × 每边搜+判+可能再搜）。

| 配置 | 建议默认 |
| --- | --- |
| `advanced_resources_max_steps` | `12` |
| `advanced_resources_max_refine` | `1` |
| `advanced_resources_max_topics` | `3` |
| `advanced_resources_judge_fallback_k` | `2` |
| `advanced_resources_use_llm_router` | `false`（选工具仍默认规则；**判定改写默认开**） |

**说明：** 「LLM 选下一个工具名」默认关；「LLM 判定相关性并改写 query」是产品默认能力，与 router 开关分开。

`plan` 响应带轨迹，例如：

```json
{
  "steps": [
    { "tool": "summarize_weak_points", "ok": true, "data": { "weak_points": ["动态规划"] } },
    { "tool": "search_course", "ok": true, "data": { "query": "动态规划", "candidates": 5 } },
    {
      "tool": "judge_relevance",
      "ok": true,
      "data": {
        "keep": 0,
        "need_refine": true,
        "refined_query": "动态规划 状态转移方程 例题",
        "reason": "候选多为无关讲义目录"
      }
    },
    { "tool": "search_course", "ok": true, "data": { "query": "动态规划 状态转移方程 例题", "candidates": 4 } },
    { "tool": "judge_relevance", "ok": true, "data": { "keep": 2, "need_refine": false } }
  ],
  "weak_points": ["动态规划"],
  "course": [/* 仅 keep */],
  "external": [/* 仅 keep */],
  "error_type": null
}
```

最终列表**只含 keep**；轨迹里可保留候选数量便于上课讲解，但不把 drop 项当作推荐结果。

## 6. 编排实现（自研，无 LangGraph）

```text
for topic in weak_points[:max_topics]:
  for channel in (course, external):
    query = topic
    refine_left = max_refine
    while True:
      hits = search_*(query)
      judged = judge_relevance(topic, channel, hits, query)
      if judged.keep:
        accept(judged.keep); break
      if judged.need_refine and refine_left > 0:
        query = judged.refined_query
        refine_left -= 1
        continue
      break  # 无 keep 且不能再 refine → 该 channel 空
```

`dispatch`：`dict[str, Callable]`。有第一个工具再加文件，不预建空 `agents/` 包。

## 8. 错误语义

| 情况 | 行为 | 建单 |
| --- | --- | --- |
| 无 student | 403 | 否 |
| 未知工具 | 400/422 | 否 |
| 课外搜索失败 | step 失败；课内 keep 仍返回 | 否 |
| judge 上游失败 | fallback 顶 K + 审计 | 否 |
| 改写后仍无 keep | 该 topic×channel 为空，不填假链接 | 否 |
| 知识库无片段 | `ok=true` + 空候选 | 否（≠ ask miss） |

## 10. 验收标准

1. 白名单外工具无法执行。
2. `search_course` 不出 `company`。
3. 构造「标题明显跑题」的候选时，最终 `course`/`external` **不含**这些项（单测 mock judge 或固定 prompt 夹具）。
4. keep 为空且 `need_refine` 时，轨迹中出现第二次 `search_*` 且 query 与首轮不同。
5. refine 次数不超过配置；无死循环。
6. 课外失败不抹掉课内 keep；不建单；无 `hit=false`。
7. `/ask` 回归通过；无 langgraph 依赖。

## 11. 实现顺序建议

1. `search_*` + `judge_relevance` + 单测（筛选与 refine）。  
2. `plan` 规则闭环（按 topic×channel）。  
3. `summarize_weak_points` 接入 + API。  
4. 前端轨迹展示。  
5. （可选）学习路径回灌同一套判定，改善现网无关推荐。
