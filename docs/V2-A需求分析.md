| 对应基线 | `docs/需求分析.md` 第 8.1、8.3、9–11 节；`docs/系统架构设计.md` 第 10.2 节；`docs/任务拆分.md` V2-A 表 |

本文说明 **V2-A 学伴做什么、不做什么、如何验收**，并对照当前仓库给出差距。实施任务见后续 `docs/V2-A任务拆分.md`（本文不拆实现步骤）。

## 1. 背景与目标

### 1.1 结论

V2-A 目标是在 **不重写 RAG 主链路** 的前提下，给学员侧接上「命中之后 / 未命中之后」的学伴能力：能问课程代码、能在隔离沙箱里看报错、能批改作业、能推荐已入库资料、能把截图送进既有问答。

智能助手（代码仓解释、实验配置、内部评审等）留在 V2-B，本文不展开。

### 1.2 相对 V1 的增量


| 能力   | V1                     | V2-A                                      |
| ---- | ---------------------- | ----------------------------------------- |
| 知识源  | 手动上传 MD/PDF/docx       | 增加课程代码/课件；切片带来源路径（及符号名）                   |
| 问答   | `/ask` 文本提问            | 仍走同一检索；问代码必须带来源路径或文档标题                    |
| 未命中  | 学员建工单                  | 不变；**沙箱失败、OCR 失败不得建单，也不得伪装成** `hit=false` |
| 调试   | 无                      | 粘贴报错/代码 → 隔离沙箱执行 → 分析或明确失败                |
| 批改   | 无                      | 对比参考答案与提交；只出判断与建议                         |
| 学习路径 | 无                      | 按提问历史识别薄弱点，只推荐课程空间已有资料                    |
| 多模态  | 无                      | 截图/公式 OCR 后进入 `/ask`                      |
| 部署   | Compose：API + Postgres | Compose **可选**增加学伴沙箱容器                    |
| 界面 | 产品入口 Vue 3（`docs/产品化前端需求分析.md`） | 学伴页随 A1–A5 接口接入同一 Vue |




### 1.3 硬约束（继承 MVP/V1，V2-A 不得破坏）

1. 单体 FastAPI + PostgreSQL/pgvector；不为学伴另起一套检索服务或向量库。
2. 空间过滤必须在检索 SQL 的 `WHERE` 中；插件禁止全库检索后再用 Python 过滤。
3. 客户端不得决定 `space_ids`；工具入参同样不得带可检索空间。
4. 未命中或低于阈值时不调用 DeepSeek；来源只来自召回记录（含代码切片的 path）。
5. 系统故障（502/503）、知识库未命中（200 + `hit=false`）、**工具失败** 三种语义必须区分。
6. 对话与批改意见不得自动写入知识库；参考答案全文不对学员开放。
7. 不为 V2 预建空的 `agents/` 包；有第一个学伴工具再加文件。
8. 学伴工具的知识上下文默认只使用 `student` 空间，即使教学岗 `allowed_spaces` 含 `company`（见 4.2）。

## 2. 范围与非目标



### 2.1 V2-A 范围内

对应任务拆分 V2-A1～A5。界面跟现有 Vue 产品入口，不单独立项 A6。

- **V2-A1 课程代码/课件入库：** 教学岗上传 zip/目录；按文件切片写入 `student`；切片带 path + language。问答来源含 path 或文档标题。内部仓不得进入 `student`。第一期不做 tree-sitter 符号、不做 Git clone。
- **V2-A2 代码调试助手：** 学员（及教学岗以学伴身份）粘贴报错或代码；Agent 在隔离沙箱执行 Python/C++；返回分析或沙箱失败；无 DB 密钥、无上传目录写权限、无任意出网。
- **V2-A3 作业智能批改：** 对比参考答案与学员提交；输出正确性判断 + 改进建议；不改成绩、不代交作业。
- **V2-A4 学习路径：** 根据提问历史（及可选测验记录）识别薄弱点；推荐条目必须能在 `student` 空间找到对应文档。
- **V2-A5 OCR：** 代码截图 / 公式图 → 识别文本 → 既有 `/ask`；OCR 失败 ≠ 知识库未命中。

学伴相关按钮与结果展示：产品入口见 `docs/产品化前端需求分析.md`；V2-A 第一期不阻塞该前端，学伴页在对应 API 就绪后接入同一 Vue。



### 2.2 V2-A 明确不做

- V2-B 全部：内部代码仓索引、实验助手、技术文档生成、Wiki/Issue FAQ、代码审查、Git 只读。
- 把学伴做成第二套 FastAPI / 第二套 pgvector。
- 在学伴插件任务内重做一套前端框架（产品 Vue 由 `docs/产品化前端需求分析.md` 单独立项，与 A1–A5 并行）。
- 对话自动入库、无人确认写知识库。
- 对接课程平台 **触发改分**（默认不做；若以后要做须单独批准）。
- 代写作业、输出 `company` 空间代码或路径给学员。
- 学员用沙箱访问内网、数据库、宿主机 Docker socket。
- 完整在线 IDE、全功能 Wiki、考试系统、入职带练。
- Redis / Celery / 对象存储 / 混合检索 / rerank（除非评测证明当前链路不够）。
- LangChain / LlamaIndex 作为内核。



### 2.3 已拍板（本专项）

1. **课程代码进库：** 教学岗上传 zip/目录，复用现有上传鉴权；空间强制 `student`。不在 A1 做 Git clone。
2. **来源粒度：** 第一期切片必须带仓库相对路径 + language；不要求 tree-sitter 符号名（函数/类）。问「某段代码含义」带来源 path 或文档标题即可。
3. **学伴界面：** 产品主入口为 Vue 3（见产品化前端需求）；A1–A5 仍可用 API 验收。本专项不包含 Gradio / SSE。

### 2.4 待确认（不阻塞 A1 开工，实现对应任务前需拍板）

1. **沙箱镜像、超时、CPU/内存上限：** 建议本机 Compose 独立容器。
2. **OCR 引擎：** 选型建议 PaddleOCR。
3. **学习路径是否要测验：** 第一期建议只用 V1 会话历史 + 课程空间检索。
4. **zip 内忽略规则：** 建议忽略 `.git`、常见二进制、超大文件；具体名单实现 A1 时定。
5. **演示用课程代码包路径结构**（虚构课程即可）。

## 3. 统一术语


| 术语     | 含义                                               |
| ------ | ------------------------------------------------ |
| 学伴插件   | 只服务课程场景的工具；知识上下文默认 `student`                     |
| 来源路径   | 代码/课件切片上的仓库相对路径（如 `labs/sort.py`），由入库记录生成，不由模型编造 |
| 沙箱     | 与 API 进程隔离的执行环境；无知识库写权限、无业务库凭证                   |
| 工具失败   | 沙箱超时/崩溃、OCR 识别失败等；不是 `hit=false`，不建学员工单          |
| 参考答案   | 作业的标准答案；仅教学岗/助教可见全文                              |
| 学伴身份使用 | 学员，或教学岗在调用学伴接口时被服务端裁剪为仅 `student`                |


角色和空间标识仍为：`student`、`employee`、`teaching`（展示语义）、`company`。

## 4. 角色与权限



### 4.1 谁能用学伴能力


| 身份         | A1 入库 | A2 调试    | A3 提交批改 | A3 看参考答案全文 | A4 路径 | A5 OCR |
| ---------- | ----- | -------- | ------- | ---------- | ----- | ------ |
| 学员         | 否     | 是        | 是       | 否          | 是     | 是      |
| 内部员工（非教学岗） | 否     | 否        | 否       | 否          | 否     | 否      |
| 教学岗        | 是     | 是（学伴上下文） | 可代测     | 是          | 是     | 是      |


未登录一律 401。普通员工没有 `student` 成员关系，学伴接口返回 403，不得因为教学岗演示而让员工检到课程代码之外的内部仓。

### 4.2 学伴工具的空间裁剪（关键）

`/ask` 仍按 V1：`allowed_spaces` 来自 `space_members`（教学岗为两空间）。

学伴插件 **不得** 把教学岗的全部 `allowed_spaces` 送进沙箱或批改上下文。学伴工具服务端固定使用 `student`（若用户对该空间无成员关系则 403）。

理由：教学岗若把 `company` 切片带进沙箱或批改 Prompt，会把内部实现泄露到学伴会话。

### 4.3 禁止事项

- 客户端传 `space_ids` / `role` 改变工具可见范围。
- 学员响应中出现 `company` 的标题、路径、片段、文档 ID。
- 沙箱进程读取 `DATABASE_URL`、`.env`、上传目录。
- 用模型编造仓库路径、作业分数、外链课程。

## 5. 关键业务流程



### 5.1 课程代码入库（A1）

```text
教学岗登录
  → 上传课程代码 zip 或目录（空间由服务端定为 student）
  → 按文件解析；跳过无关文件（建议忽略 .git、二进制、超大文件，名单待确认）
  → 切片写入 chunks：content + embedding + space_id=student + path + language
  → 失败文件/条目 status=failed，不参与检索
```

问答仍走 `/ask`。命中代码切片时，`sources` 必须带 path（或文档标题）；path 来自数据库字段，模型不得改写来源列表。

### 5.2 调试（A2）

```text
学员粘贴报错或代码
  → 登录与学伴空间校验
  → （可选）在 student 内检索相关讲义/代码片段，作为分析上下文
  → 沙箱执行（有超时与资源上限）
        ├─ 沙箱成功：把运行输出交给生成，给出修复建议；来源仍只来自召回
        └─ 沙箱失败：返回独立错误（超时/非零退出/环境错误），不调用「未命中建工单」
  → 禁止把 company 片段或内部路径放入 Prompt / 沙箱工作区
```

Agent 为自研小循环（选工具 → 执行 → 再生成），工具白名单仅：沙箱执行、课程空间检索。禁止任意 Shell、任意出网。

### 5.3 作业批改（A3）

```text
教学岗创建作业（题面 + 参考答案，写入 student，参考答案标记仅教师可见）
  → 学员提交代码或文本
  → 服务端取参考答案（学员 API 不得返回参考答案全文）
  → （可选）沙箱跑公开测试
  → LLM 对比提交与参考答案，输出判断 + 建议
  → 不调用成绩 API；不改 users 以外的「分数」字段
```



### 5.4 学习路径（A4）

```text
读取该学员近期会话问题（V1 messages 已有）
  → 在 student 内检索相关资料
  → 生成「薄弱点 + 推荐条目」
  → 每条推荐必须带真实 document_id 或 path
  → 检索为空则说明没有可推荐资料，禁止编造站外课程链接
```

第一期可不建测验；若以后加测验，记录进 `learner_signals`，仍只推荐已入库资料。

### 5.5 OCR（A5）

```text
学员上传图片
  → OCR
        ├─ 成功：文本作为问题或代码，进入既有 /ask 或调试入口
        └─ 失败：返回 ocr_failed，不建工单，不把失败说成知识库未命中
```

## 6. 数据与接口增量



### 6.1 表（相对 V1）


| 表或字段                                    | 用途           | V2-A 是否必须            |
| --------------------------------------- | ------------ | -------------------- |
| `chunks.path` / `chunks.language`（或等价列） | 代码/课件来源路径与语言 | A1 必须                |
| `assignments` / `submissions`           | 作业与提交        | A3 必须                |
| `knowledge_points` / `learner_signals`  | 知识点与薄弱记录     | A4 可选；第一期可用会话 + 检索代替 |
| 沙箱/OCR 无独立业务表也可                         | 失败靠日志与响应字段   | 可以                   |


有能力再建模，不预建空表。A1 未开始前不要加无调用方的 `code_symbols` 表；符号可先落在切片元数据。

### 6.2 接口增量（建议）

具体路径在任务拆分中可微调，语义不得偏离。


| 接口                                                                                 | 说明                       |
| ---------------------------------------------------------------------------------- | ------------------------ |
| 已有 `/ask` `/documents` `/login` 等                                                  | 保持；学伴问答仍登录态              |
| `POST /documents` 或 `POST /code-ingest`                                            | 课程代码包入库；空间强制 `student`   |
| `POST /debug`                                                                      | 粘贴报错/代码；返回分析或沙箱错误        |
| `POST /assignments`、`POST /assignments/{id}/submit`、`POST /assignments/{id}/grade` | 教师出题；学员提交；批改结果           |
| `GET /learning-path`                                                               | 当前学员的推荐列表                |
| `POST /ocr` 或 `/ask` 支持图片                                                          | OCR 后进入问答                |
| `GET /ask/stream` | 本专项不做 SSE |


`/debug`、`/ocr` 的成功响应不得把工具失败写成 `hit=false`。

## 7. 错误语义与审计


| 场景           | HTTP / 业务语义                       | 是否建学员工单     | 是否调 DeepSeek  |
| ------------ | --------------------------------- | ----------- | ------------- |
| 未登录          | 401                               | 否           | 否             |
| 员工调学伴接口      | 403                               | 否           | 否             |
| 知识库未命中       | 200，`hit=false`                   | 是（学员，V1 规则） | 否             |
| DeepSeek 失败  | 502                               | 否           | —             |
| DB / 向量模型未加载 | 503                               | 否           | 否             |
| 沙箱超时/崩溃/非零退出 | 200 或 4xx，`error_type=sandbox_*`  | 否           | 失败路径默认不再装成未命中 |
| OCR 失败       | 200 或 4xx，`error_type=ocr_failed` | 否           | 否             |
| 无可推荐资料       | 200，推荐列表空 + 说明                    | 否           | 可不调或仅总结历史     |


审计在 V1 字段上增加：工具名、工具成功/失败、沙箱是否执行、OCR 是否成功、引用 path 列表。仍不得把 `company` 路径写入学员侧日志展示。

## 8. 验收标准（学伴关卡）

与 `docs/需求分析.md` 第 11 节「V2 学伴」对齐：

1. 课程代码或讲义入库后，学员能问「某段代码含义」或算法原理，来源含文档标题或仓库路径；路径来自数据库。
2. 同一套内部代码 **不得** 出现在 `student` 检索中；学员问内部模块名，答案和来源中无该仓路径。
3. 粘贴报错：得到基于沙箱输出的分析，或明确沙箱失败；沙箱容器无 DB 密钥；响应中无 `company` 内容。
4. 批改给出正确性判断与建议；不改成绩；学员拉取作业详情看不到参考答案全文。
5. 学习路径每条推荐能在 `student` 空间对应到文档或 path；无依据则不推荐外链课程。
6. 截图能走通问答，或返回 OCR 失败；失败响应的 `hit` 不得为 false（除非 OCR 成功后检索确实未命中）。
7. 检索 SQL 仍含 `chunks.space_id = ANY(...)` 与 `documents.status = 'ready'`。

A6 本专项不做。命中判断与鉴权仍只在 FastAPI。

## 9. 现状差距（相对当前仓库）

对照时间点：V1-T1～T7 已落地；切片为纯文本窗口，无 path/language；无沙箱、无作业表、无 OCR。


| 任务                    | 状态      | 说明                                                |
| --------------------- | ------- | ------------------------------------------------- |
| V2-A1 代码/课件路径入库       | **未开始** | `chunks` 无 path/language；解析仅 md/txt/pdf/docx      |
| V2-A2 调试沙箱            | **未开始** | Compose 仅 postgres + api；无隔离执行                    |
| V2-A3 作业批改            | **未开始** | 无 assignments/submissions                         |
| V2-A4 学习路径            | **未开始** | 有 conversations/messages 可作信号，无推荐接口               |
| V2-A5 OCR             | **未开始** | `/ask` 仅文本                                        |
| V2-A6 Gradio/SSE/独立前端 | **本专项不做** | 学伴页接入现有 Vue |




### 9.1 风险

1. 教学岗两空间成员若原样传入沙箱/批改，会泄露 `company`。
2. 检索阈值过低时，调试/OCR 后的 `/ask` 仍会「假命中」，与 V1 工单问题同类。
3. 沙箱镜像体积与 Windows Docker 资源；须在文档写明超时，避免当成 502。
4. 过早引入 Vue/Gradio 会把工期从插件挪到换皮；A1–A5 不依赖新前端也能用 API 验收。



### 9.2 建议落地顺序

```text
V2-A1 课程代码路径入库
    │
    ├─► V2-A5 OCR（可与 A1 并行，都接到 /ask）
    │
    ▼
V2-A2 沙箱调试（Compose 增沙箱服务）
    │
    ▼
V2-A3 作业批改（可复用沙箱跑公开测试）
    │
    ▼
V2-A4 学习路径（复用 V1 会话 + student 检索）
```

学伴入口同步做进 Vue，不单独排 A6。
