# T13 端到端验收复现步骤

本说明用于固定 `docs/任务拆分.md` 中 T13 的验收流程，确保他人可重复执行并得到一致结论。

## 验收目标

- 文档可成功入库并变为 `ready`。
- `student` 仅能检索 `student` 空间。
- `employee` 仅能检索 `company` 空间。
- `teaching` 可检索两个空间。
- 知识库未命中时固定拒答，且 `sources=[]`。
- 可验证检索 SQL 包含空间过滤与 `ready` 状态条件。

## 前置条件

1. Python 3.11+。
2. Docker Desktop 可用（用于 PostgreSQL + pgvector）。
3. `.env` 已配置 `CHAT_API_KEY`（命中问答会调用 DeepSeek）。

## 样例文档

- `docs/samples/t13/student_course_sample.md`
- `docs/samples/t13/company_policy_sample.md`

两份文档均为虚构内容，不包含真实内部信息。

## 一键执行

在仓库根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run_t13_acceptance.ps1
```

脚本会自动完成：

1. `docker compose up -d`。
2. 启动本地 API（`uvicorn app.main:app`）。
3. 健康检查（API、数据库、向量模型）。
4. 上传两份样例文档并确认 `ready` 和 `chunk_count > 0`。
5. 使用演示账号登录后，执行隔离与未命中场景问答断言。
6. 运行 `tests/test_retrieve.py` 中的 SQL 约束断言。

演示账号（密码默认 `demo1234`，或使用环境变量 `DEMO_PASSWORD`）：

- `student_demo`
- `employee_demo`
- `teaching_demo`

若本机已手动启动 API，可使用：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run_t13_acceptance.ps1 -SkipStartApi
```

## 通过标准对应关系

- 学员问课程：`hit=true` 且来源非空（来自 `student`）。
- 学员问公司制度：`hit=false`，来源为空，返回固定拒答。
- 员工问公司制度：`hit=true` 且来源含 `company`。
- 教学岗分别问课程/公司：均 `hit=true` 且来源空间正确。
- 无答案问题：`hit=false`、`sources=[]`、固定拒答文案。
- SQL 验证：`WHERE chunks.space_id = ANY(...)` 且 `documents.status = 'ready'` 存在于检索语句。
