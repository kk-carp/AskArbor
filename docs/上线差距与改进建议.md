# 相对可上线系统的改进清单

| 项 | 内容 |
| --- | --- |
| 文档性质 | 对照当前 FDE 课程仓库与「可长期对外/对内正式使用」系统的差距 |
| 对照基线 | 现仓库已实现：隔离 RAG、登录会话、文档管理、工单/负责人、OCR、进阶资料推荐、轻量入职检索增强、SSE 流式问答、来源 `snippet` 预览 |
| 说明 | 本项目定位是 **可演示、可验收的课程实践**，不是生产基线；下列项按优先级分组，不要求一次做完 |

---

## 1. 结论先看

当前系统已经具备「能跑通、能隔离、能带来源拒答」的 RAG 内核，适合课程演示与内网小范围试用。

若要接近真正上线，缺口主要不在「再做一个问答框」，而在：

1. **身份与权限**（SSO、真实组织、细粒度 ACL）
2. **知识运营**（同步、版本、审核、下线与审计）
3. **检索质量与评测闭环**
4. **可靠性与运维**（异步入库、限流、备份、可观测）
5. **安全与合规**（密钥、上传、日志脱敏、依赖供应链）

下面按主题列出可改进项，并标注建议优先级：`P0` 上线前几乎必需，`P1` 正式使用很快会痛，`P2` 增强体验/规模。

## 2. 安全与账号体系

| 项 | 现状（约） | 上线缺口 | 优先级 |
| --- | --- | --- | --- |
| 登录 | 自建用户名密码 + Session Cookie；演示账号仅 `APP_ENV=local` 自动写入；`prod` 拒绝默认密钥/演示密码 | 接 SSO/飞书/企业微信；强制改密、锁定、密码策略 | P0 |
| 会话 | Starlette Session；`prod` 下 Cookie `https_only` | 分区 Cookie、会话吊销、并发登录策略 | P0 |
| 授权 | 角色 + 空间成员（`student`/`company`）粗粒度 | 文档/目录级 ACL、按部门/项目可见；管理员操作审计 | P0 |
| CSRF / CORS | 同源代理为主 | 明确 CSRF 策略；生产 CORS 白名单 | P0 |
| 密钥 | `.env` 本地文件 | 密钥托管（KMS/Vault）、轮换；禁止镜像内嵌密钥 | P0 |
| 上传 | 本地磁盘、类型/大小校验有限 | 病毒扫描、类型白名单加固、对象存储、路径穿越与 zip bomb 防护加强 | P0 |
| 依赖与镜像 | `requirements.txt` / Compose | 依赖锁定与漏洞扫描、镜像签名、最小权限运行 | P1 |

## 3. 数据、入库与知识运营

| 项 | 现状（约） | 上线缺口 | 优先级 |
| --- | --- | --- | --- |
| 存储 | 文件在 `data/uploads/`，元数据在 Postgres | 对象存储（S3/MinIO）；多副本；备份/恢复演练 | P0 |
| 入库 | API 进程内同步解析/切片/向量 | 大文件/大批量异步队列；失败重试；进度与部分成功可观测 | P0 |
| 状态机 | `ready` / 失败可区分，但运营面薄 | 重解析、版本号、上线审批、定时失效；变更影响面提示 | P1 |
| 外部知识 | 手传为主；飞书等未接 | 飞书/Wiki/Git **同步入库**（本地仍为检索真相源）；`source_system` + `external_id` | P1 |
| 代码仓 | 课程 zip 强制 `student`；公司仓路径能力弱 | company 代码包入库、增量同步、分支/权限映射 | P1 |
| Schema 变更 | `create_all` + 少量 `ALTER IF NOT EXISTS` | 正式迁移工具（Alembic）与回滚策略 | P1 |
| 演示种子 | 固定 demo 用户与样例；`prod` 不自动写 demo 用户 | 生产种子与演示种子隔离（已禁止生产自动写 demo 密码）；样例 topic_owners 仍可再拆 | P0 |

## 4. RAG 质量与答案可信度

| 项 | 现状（约） | 上线缺口 | 优先级 |
| --- | --- | --- | --- |
| 检索 | dense + 词法（tsvector/jieba）+ RRF + BGE reranker（默认双开） | 按空间/场景校准 `rerank_min_score`；按文档类型分索引可选 | P1（校准中） |
| 切片 | 固定窗口 | 按标题/代码符号/表格结构切片；重叠与长度可配置并评测 | P1 |
| 假命中 | 低阈值易捞无关片段 | 评测集驱动调参；拒答与「依据不足」文案统一；来源摘要高亮 | P0 |
| 来源体验 | 返回 `document_id`/title/path/score/`snippet`；前端标题可点 `GET /documents/{id}/file`（按允许空间校验，非教学岗管理门） | 原文内定位/高亮；过期文档标记。不要把 snippet 当未做项重做 | P1 |
| 多轮 | 历史拼进 prompt，检索仍本轮问句 | 指代消解/查询改写（仍受空间约束）；避免历史污染检索 | P1 |
| 入职增强 | 关键词 + 岗位中文名拼 query | 岗位画像、目录映射、效果评测；误触发率监控 | P2 |
| OCR | Qwen-VL + 可选 Paddle；截图作答依据 | 版面复杂表/公式评测；失败率与成本看板；图片是否持久化策略 | P1 |
| 评测 | 有 phase1 脚本与样例 | 持续回归（命中率、拒答率、越权、延迟、$/问）；上线门禁 | P0 |

对应代码主链可参考：`ingest_service` → `parsers`/`chunker`/`embed` → `retrieve` → `qa_service` → `generate`。

## 5. 产品功能（相对「能日常用」）

| 项 | 现状（约） | 上线缺口 | 优先级 |
| --- | --- | --- | --- |
| 前端 | Vue 问答/文档/工单/进阶资料推荐 | 无障碍、移动端、空态与错误统一；权限菜单按角色收紧 | P1 |
| 流式输出 | 已做：`POST /ask/stream` SSE（命中判断在出字前完成，未命中不调模型）；前端问答走流式 | 首字延迟、弱网重连可再优化；不要按「未做」再补一遍流式 | P2 |
| 工单 | 学员未命中建单、简单回复 | SLA、通知（邮件/飞书）、统计、重复单合并 | P1 |
| 负责人 | 主题关键词匹配 | 运营后台维护、覆盖率报表、升级路径 | P1 |
| 进阶资料推荐 | 白名单工具 + 相关性闭环 + 文章 + 缓存 | 个性化与效果追踪；搜索配额与失败降级更完善 | P2 |
| Skill / Agent | 不做 SkillHub 对接 | 若做教学 Agent：本仓白名单工具即可，不接公司注册中心 | P2（可选专项） |
| 作业批改 | 暂缓 | 若恢复：人审、不对接触发改分、防作弊 | P2 |
| 多租户 | 单库双空间 | 组织/租户隔离、配额、计费（若对外 SaaS） | P2 |

## 6. 可靠性、性能与部署

| 项 | 现状（约） | 上线缺口 | 优先级 |
| --- | --- | --- | --- |
| 部署 | Compose：API + Postgres；BGE 进 API 进程 | 无状态 API 多副本；Embedding 独立服务或批量 GPU；健康检查与滚动发布 | P0 |
| 数据库 | 单实例 pgvector | 主从/备份、连接池、慢查询；向量索引（HNSW 等）按数据量启用 | P0 |
| 限流与超时 | 登录/问答进程内按用户名+IP 或用户限流；超限 429，文案与知识库未命中分开；部分上游超时 | 多副本共享计数（Redis）；队列背压；熔断与降级文案 | P0 |
| 大模型依赖 | DeepSeek 同步调用 | 多供应商兜底、重试抖动、成本上限 | P1 |
| 并发入库/问答 | 同进程 CPU/内存争用 | 入库 Worker 与问答分离；水平扩展策略 | P0 |
| 配置 | `.env` + `APP_ENV=local/prod` | staging；更多特性开关 | P1 |

## 9. 建议落地顺序（若要以「内网正式试用」为目标）

```text
P0 安全底座
  SSO/强密码、HTTPS、密钥托管、备份恢复、限流、基础监控告警
    │
    ▼
P0 质量门禁
  评测集 + 阈值/拒答校准 + 越权回归（每次发版必跑）
    │
    ▼
P1 知识运营
  异步入库、对象存储、文档版本/下线审批；可选飞书同步适配器
    │
    ▼
P1 体验
  来源可打开原文（已按空间权限出链）、工单通知（流式输出与来源 snippet 已落地，勿再列入本步）
    │
    ▼
P2 场景扩展
  公司 Skill、更细岗位推荐、批改等（单独需求，不阻塞试用）
```

## 10. 明确「不必为了上线而做」的项

与课程范围一致、且对内网知识助手价值有限或成本过高的，可继续不做或延后：

- 为学伴/助手拆两套微服务或两套向量库
- 代码执行沙箱 / 任意 Shell Agent
- 用 LoRA 替换线上 BGE/对话主模型作为默认路径
- 未拍板就对接任意外部 Skill 或任意出网
- 为未来飞书预建空模块（有同步需求再加适配器即可）

## 12. 一句话

**课程版验证的是「隔离 RAG 能不能答对、能不能拒答」；上线版要补的是「谁能看、怎么运维、坏了怎么办、答错了如何发现并改进」。**
