| 项 | 内容 |
| --- | --- |
| 文档性质 | 对照当前 FDE 课程仓库与「可长期对外/对内正式使用」系统的差距 |
| 对照基线 | 现仓库已实现：隔离 RAG、登录会话、文档管理、工单/负责人、OCR、进阶资料推荐、轻量入职检索增强、SSE 流式问答、来源 `snippet` 预览；`dev` 另有环境门禁、登录/问答限流、`request_id`、过期清理、教学岗指标、按空间打开原文、发版 `--gate`、登录/问答短免责声明、入库内容去重与下线后删除、用户删除会话/可见工单 |
| 说明 | 本项目定位是 **可演示、可验收的课程实践**，不是生产基线；下列项按优先级分组，不要求一次做完。课堂 RAG 内核仍以 `main` 为准；下列「已做」指 `dev` 内网试用加固，不要当未做项重做 |

## 1. 结论先看

当前系统已经具备「能跑通、能隔离、能带来源拒答」的 RAG 内核，适合课程演示与内网小范围试用。`dev` 已补环境门禁、限流、过期清理、进程内指标、发版评测门禁、短免责声明、prod Origin 校验和登录勾选须知。

若要接近真正上线，缺口主要不在「再做一个问答框」，而在：

1. **身份与权限**（SSO、真实组织、细粒度 ACL；`prod` 已校验带登录 Cookie 的写请求 Origin/Referer）
2. **知识运营**（同步、版本、审核、下线与审计）
3. **检索质量与评测闭环**（`--gate` 已能挡隔离/未命中调模型；阈值校准仍可加强）
4. **可靠性与运维**（异步入库、**备份恢复**、多副本可观测；进程内限流已有）
5. **安全与合规**（密钥托管、上传加固、登录勾选须知已挡前端、依赖供应链）

下面按主题列出可改进项，并标注建议优先级：`P0` 上线前几乎必需，`P1` 正式使用很快会痛，`P2` 增强体验/规模。

## 2. 安全与账号体系

| 项 | 现状（约） | 上线缺口 | 优先级 |
| --- | --- | --- | --- |
| 登录 | 自建用户名密码 + Session Cookie；演示账号仅 `APP_ENV=local` 自动写入；`prod` 拒绝默认密钥/演示密码 | 接 SSO/飞书/企业微信；强制改密、锁定、密码策略 | P0 |
| 会话 | Starlette Session；`prod` 下 Cookie `https_only` | 分区 Cookie、会话吊销、并发登录策略 | P0 |
| 授权 | 角色 + 空间成员（`student`/`company`）粗粒度 | 文档/目录级 ACL、按部门/项目可见；管理员操作审计 | P0 |
| CSRF / CORS | 无 `CORSMiddleware`（默认拒跨域）；Cookie `SameSite=lax`；Vite 开发代理同源 Cookie。`APP_ENV=prod` 时，带登录 Cookie 的写请求须 Origin/Referer 与 Host 一致，否则 403 | 禁止生产 CORS `*`。local 不启用该校验，以免打断 `:5173` 代理与课上 TestClient。不要按「完全没做同源」或「未做 Origin 校验」重做 | P0 |
| 密钥 | `.env` 本地文件；`prod` 拒绝默认 `SECRET_KEY` | 密钥托管（KMS/Vault）、轮换；禁止镜像内嵌密钥 | P0 |
| 上传 | 本地磁盘；扩展名/大小白名单；课程 zip 拒路径穿越，并限制成员数与总字节 | 病毒扫描、MIME/魔数、对象存储 | P0 |
| 依赖与镜像 | `requirements.txt` / Compose | 依赖锁定与漏洞扫描、镜像签名、最小权限运行 | P1 |

## 3. 数据、入库与知识运营

| 项 | 现状（约） | 上线缺口 | 优先级 |
| --- | --- | --- | --- |
| 存储 | 文件在 `data/uploads/`（Compose 卷 `uploads`），元数据在 Postgres 卷 `pgdata` | 对象存储（S3/MinIO）仍延后。单机 `pg_dump` + 上传目录备份说明按当前安排暂缓 | P0 |
| 入库 | API 进程内同步解析/切片/向量。同空间相同内容（SHA-256）对 `ready`/`processing` 返回 409，教学岗可选择不传或 `replace` 下线旧文档再入。课程 zip 未做该门禁 | 大文件/大批量异步队列；失败重试；进度与部分成功可观测 | P0 |
| 状态机 | `ready` / 失败可区分，但运营面薄 | 重解析、版本号、上线审批、定时失效；变更影响面提示 | P1 |
| 外部知识 | 手传为主；飞书等未接 | 飞书/Wiki/Git **同步入库**（本地仍为检索真相源）；`source_system` + `external_id` | P1 |
| 代码仓 | 课程 zip 强制 `student`；公司仓路径能力弱 | company 代码包入库、增量同步、分支/权限映射 | P1 |
| Schema 变更 | `create_all` + 少量 `ALTER IF NOT EXISTS` | 正式迁移工具（Alembic）与回滚策略 | P1 |
| 演示种子 | 固定 demo 用户与样例；`prod` 不自动写 demo 用户 | 生产种子与演示种子隔离（已禁止生产自动写 demo 密码）；样例 topic_owners 仍可再拆 | P0 |

## 4. RAG 质量与答案可信度

| 项 | 现状（约） | 上线缺口 | 优先级 |
| --- | --- | --- | --- |
| 检索 | dense + 词法（tsvector/jieba）+ RRF + BGE reranker（默认双开） | 按空间/场景校准 `rerank_min_score`；按文档类型分索引可选 | P1（校准中） |
| 切片 | 固定窗口 | 按标题/代码符号/表格结构切片；重叠与长度可配置并评测 | P1 |
| 假命中 | 低阈值易捞无关片段 | 评测集驱动调参；拒答与「依据不足」文案统一；来源摘要高亮 | P0 |
| 来源体验 | 返回 `document_id`/title/path/score/`snippet`；前端标题可点 `GET /documents/{id}/file`（按允许空间校验，非教学岗管理门） | 原文内定位/高亮；过期文档标记。不要把 snippet 当未做项重做 | P1 |
| 多轮 | 历史拼进 prompt，检索仍本轮问句 | 指代消解/查询改写（仍受空间约束）；避免历史污染检索 | P1 |
| 入职增强 | 关键词 + 岗位中文名拼 query | 岗位画像、目录映射、效果评测；误触发率监控 | P2 |
| OCR | Qwen-VL + 可选 Paddle；截图作答依据 | 版面复杂表/公式评测；失败率与成本看板；图片是否持久化策略 | P1 |
| 评测 | 有 phase1 脚本与 12 条作业集；`--gate` 时隔离非 100% 或未命中却调模型则非 0 退出，并追加员工越权样本 | 持续回归（命中率、延迟、$/问）仍可加强；不要把 `--gate` 当成课上作业步骤 | P0 |

对应代码主链可参考：`ingest_service` → `parsers`/`chunker`/`embed` → `retrieve` → `qa_service` → `generate`。

## 6. 可靠性、性能与部署

| 项 | 现状（约） | 上线缺口 | 优先级 |
| --- | --- | --- | --- |
| 部署 | Compose：API + Postgres；BGE 进 API 进程；postgres/api 已有 healthcheck（`/health` 要求库通且 embedding 已加载） | 无状态 API 多副本；Embedding 独立服务或批量 GPU；滚动发布。不要按「没有健康检查」重做 | P0 |
| 数据库 | 单实例 pgvector | 主从、连接池、慢查询；向量索引（HNSW 等）按数据量启用。**备份脚本尚未入库**（见第 3 节存储） | P0 |
| 限流与超时 | 登录/问答进程内按用户名+IP 或用户限流；超限 429，文案与知识库未命中分开；部分上游超时 | 多副本共享计数（Redis）；队列背压；熔断与降级文案 | P0 |
| 大模型依赖 | DeepSeek 同步调用（OpenAI 兼容客户端）。内网可把对话基址/模型名指到兼容服务，**不要**把默认改成本地小模型，也不要在 API 进程再加载一套对话权重 | 多供应商兜底、重试抖动、成本上限。不要按「未做本地 LLM」重做一条生成链路 | P1 |
| 并发入库/问答 | 同进程 CPU/内存争用 | 入库 Worker 与问答分离；水平扩展策略 | P0 |
| 配置 | `.env` + `APP_ENV=local/prod` | staging；更多特性开关 | P1 |

## 9. 建议落地顺序（若要以「内网正式试用」为目标）

```text
已做（dev，勿重做）
  环境门禁、prod Cookie https_only、登录/问答限流、X-Request-ID
  过期会话/已回复工单清理、教学岗运行概况、按空间打开原文
  `--gate` 隔离非 100% 或未命中却调模型则失败；短免责声明
  入库内容去重与下线后删除；用户删除会话/可见工单
  prod 写请求 Origin/Referer 校验（local 不启用，禁止 CORS *）；登录勾选用户须知（不改 /login）
    │
    ▼
下一步（暂缓：单机备份；仍不引入 SSO / Redis / Celery / 对象存储）
  单机 pg_dump + data/uploads 备份恢复说明（仍是 Compose 卷）
    │
    ▼
仍延后
  SSO/密钥托管、异步入库、对象存储、会话吊销、阈值/拒答校准
  工单通知、集中日志/Prometheus（流式与来源 snippet 已落地，勿再列入）
    │
    ▼
P2 场景扩展
  公司 Skill、更细岗位推荐、批改等（单独需求，不阻塞试用）
```

## 10. 明确「不必为了上线而做」的项

与课程范围一致、且对内网知识助手价值有限或成本过高的，可继续不做或延后：

- 为学伴/助手拆两套微服务或两套向量库
- 代码执行沙箱 / 任意 Shell Agent
- 用 LoRA 替换线上 BGE/对话主模型作为默认路径
- 未拍板就对接任意外部 Skill 或任意出网
- 为未来飞书预建空模块（有同步需求再加适配器即可）
- 把 `--gate`、短免责声明、进程内限流/指标、健康检查、prod Origin 校验、登录勾选须知当成未做项再实现一遍
- 为勾选同意去改 `/login` 请求体或课上评测脚本
- 把默认对话模型改成本地小模型，或为本地推理再加一套进程内依赖（改对话基址指向内网兼容服务即可）

## 12. 一句话

**课程版验证的是「隔离 RAG 能不能答对、能不能拒答」；上线版要补的是「谁能看、怎么运维、坏了怎么办、答错了如何发现并改进」。内网试用已补 CSRF Origin 校验和登录勾选须知；单机备份按当前安排暂缓；默认对话模型不必改成本地。**
