# 统一知识助手系统架构设计

| 项 | 内容 |
| --- | --- |
| 对应需求 | `docs/需求分析.md` V5 |
| 对应选型 | `docs/技术选型.md` |
| 当前范围 | FDE 课程实践 MVP；V1/V2 只描述扩展点，不在 MVP 预建空模块 |
| 架构形式 | 单体 FastAPI 应用 + PostgreSQL/pgvector |
| 产品形态 | 一套内核、两个场景：学伴 + 智能助手 |

本文确定系统边界、模块职责、调用关系和接口。MVP 只实现知识入库与 RAG 问答，不提前实现账号、工单、沙箱和完整管理后台。扩展时保留入库、检索、生成，不重写主链路、不拆成两套系统。

---

## 1. 系统边界

### 1.1 MVP 内部

- 上传 Markdown、TXT、PDF、DOCX。
- 选择 `student` 或 `company` 空间入库。
- 解析、切片并使用 BGE-M3 生成向量。
- 根据模拟身份限定检索空间。
- 使用 pgvector 召回相关片段。
- 命中后调用 DeepSeek 生成答案。
- 返回由服务端整理的真实文档来源。
- 未命中时固定拒答。
- 提供一张简单演示页面。

### 1.2 MVP 外部（V1/V2 再做）

- 真实登录和用户权限。
- 班主任工单、内部问题负责人。
- 文档版本管理和运营后台。
- 多轮会话、流式输出、Gradio 场景页。
- OCR、进阶资料推荐。
- 新人入职推荐（问答内）；公司 Skill 本阶段不做。
- 作业批改暂缓；符号级代码解释、实验配置、自动代码审查延后。
- 异步任务、对象存储和生产部署。

`student` 空间承载学伴课程知识；`company` 空间承载智能助手内部知识。两场景共用检索内核，差异用空间成员与后续插件表达。

---

## 2. 总体架构

MVP 只有 API 和数据库两个运行组件。`student` 对应学伴课程知识，`company` 对应智能助手内部知识，同一套检索服务按身份隔离。

```text
┌─────────────────────────────────────────────┐
│ 浏览器：简单 HTML 演示页                    │
│ 身份选择 / 文档上传 / 提问 / 答案与来源     │
└─────────────────────┬───────────────────────┘
                      │ HTTP
┌─────────────────────▼───────────────────────┐
│ FastAPI 单体应用                            │
│                                             │
│ API 层                                      │
│  ├─ 文档接口                                │
│  ├─ 问答接口                                │
│  └─ 健康检查                                │
│                                             │
│ 业务编排                                    │
│  ├─ 文档入库服务                            │
│  └─ 问答服务                                │
│                                             │
│ AI 与基础能力                               │
│  ├─ 文档解析 / 切片                         │
│  ├─ BGE-M3 Embedding                        │
│  ├─ 空间过滤 / 向量检索                     │
│  ├─ DeepSeek 生成                           │
│  └─ 本地文件存储                            │
└───────────────┬──────────────────┬──────────┘
                │ SQL              │ HTTPS
┌───────────────▼────────────┐ ┌───▼──────────────┐
│ PostgreSQL + pgvector      │ │ DeepSeek API     │
│ spaces/documents/chunks    │ │ deepseek-chat    │
└────────────────────────────┘ └──────────────────┘
```

BGE-M3 与 FastAPI 在同一进程中运行。系统只有 API 和数据库两个运行组件。

## 3. 分层与依赖规则

采用简单的四层结构，不使用复杂领域驱动设计。

| 层 | 职责 | 可以依赖 |
| --- | --- | --- |
| 接口层 | HTTP 参数校验、状态码、响应格式 | 业务服务 |
| 业务层 | 编排入库和问答流程 | AI 能力、数据访问、文件存储 |
| 能力层 | 解析、切片、向量、检索、生成 | 配置、数据访问、外部 SDK |
| 基础设施层 | 数据库、文件系统、配置、外部客户端 | 第三方库 |

依赖方向：

```text
接口层 → 业务层 → 能力层 / 基础设施层
```

规则：

- 路由中不直接写 SQL、切片或 Prompt。
- 文档解析模块不访问数据库。
- DeepSeek 模块不决定是否命中。
- 检索模块不生成答案。
- 来源由系统根据召回记录生成，不采信模型虚构的链接。
- `role` 只能由角色模块映射为空间，问答接口不接受客户端传入的任意 `space_ids`。

## 5. 模块功能

### 5.1 `main.py`：应用入口

负责：

- 创建 FastAPI 应用。
- 注册路由。
- 有 `frontend/dist` 时同源托管 Vue 产品入口；未构建时 `/` 返回 503 提示。
- 在应用启动时初始化数据库。
- 在应用启动时加载一次 BGE-M3。
- 在应用关闭时释放资源。

不负责：

- 业务判断、SQL、解析和 Prompt。

### 5.2 `config.py`：配置

负责从环境变量读取并校验：

- 数据库连接。
- DeepSeek 地址、密钥和模型。
- BGE-M3 模型名、设备和批大小。
- 上传目录、文件大小限制。
- `top_k` 和最低相似度。

配置只在这里读取，其它模块通过配置对象获取值，不直接调用 `os.getenv()`。

### 5.3 `schemas.py`：接口数据结构

定义 Pydantic 模型：

- `AskRequest`
- `AskResponse`
- `SourceItem`
- `DocumentResponse`
- `HealthResponse`

建议核心结构：

```text
AskRequest
  role: student | employee | teaching
  question: 非空字符串

AskResponse
  answer: string
  hit: boolean
  sources: SourceItem[]

SourceItem
  document_id: UUID
  title: string
  space_id: string
```

### 5.4 `db.py`：数据库连接

负责：

- 建立连接池和会话。
- 启用 pgvector 扩展。
- MVP 启动时创建表。
- 插入 `student`、`company` 两个初始空间。
- 提供事务边界。

不负责具体业务查询；具体查询放在入库或检索模块中。

MVP 不引入 Alembic。数据结构稳定后，在 V1 再加入迁移。

### 5.5 `models.py`：数据库模型

定义三张表：

**`spaces`**

- `id`
- `name`

**`documents`**

- `id`
- `space_id`
- `title`
- `file_path`
- `status`
- `error`
- `created_at`

**`chunks`**

- `id`
- `document_id`
- `space_id`
- `chunk_index`
- `content`
- `embedding vector(1024)`

约束：

- `documents.space_id` 外键指向 `spaces.id`。
- `chunks.document_id` 外键指向 `documents.id`。
- `chunks.space_id` 冗余保存并建立普通索引。
- 删除失败文档时级联删除其切片。

### 5.6 `roles.py`：模拟身份与空间策略

唯一职责是把角色转换成允许空间：

```text
student  → [student]
employee → [company]
teaching → [student, company]
```

建议公开函数：

```python
get_allowed_spaces(role) -> list[str]
```

未知角色抛出明确的参数错误。

该模块是 MVP 的模拟鉴权边界。V1 接入登录后，由真实空间成员查询替换其内部实现，检索模块不需要改。`student` / `employee` / `teaching` 分别对应学伴学员、智能助手内部人员、双场景教学岗。

### 5.7 `storage.py`：本地文件存储

负责：

- 校验扩展名和 50 MB 大小限制（`MAX_UPLOAD_BYTES`，课件 PPTX 常超过 10 MB）。
- 清理原始文件名，禁止路径穿越。
- 生成实际保存名：`{uuid}_{safe_filename}`。
- 保存到 `data/uploads/{space_id}/`。
- 入库失败时按策略清理文件。

公开函数：

```python
save_upload(file, space_id) -> StoredFile
```

不解析文件内容。

### 5.8 `parsers.py`：文档解析

负责按格式把文件转成纯文本：

```text
.md / .txt → UTF-8 读取
.pdf       → pypdf
.docx      → python-docx
```

公开函数：

```python
parse_document(path, extension) -> str
```

规则：

- 文本为空则报错。
- PDF 没有可提取文本时提示“不支持扫描件”，不做 OCR。
- 解析器不切片、不生成向量、不写数据库。

### 5.9 `chunker.py`：文本切片

负责：

- 清理连续空白。
- 按约 800 字符切片。
- 相邻片段重叠约 100 字符。
- 丢弃全空片段。
- 返回有序片段。

公开函数：

```python
split_text(text, chunk_size=800, overlap=100) -> list[str]
```

MVP 不做标题感知、语义切片和表格重建。

### 5.10 `embed.py`：向量生成

负责：

- 应用启动时加载 `BAAI/bge-m3`。
- 文档切片批量编码。
- 用户问题单条编码。
- 输出 1024 维 dense 向量。
- 对向量执行归一化，确保 cosine 比较一致。

公开函数：

```python
encode_documents(texts) -> list[list[float]]
encode_query(question) -> list[float]
```

MVP 中两者可以共用底层 `model.encode()`，保留两个函数是为了后续添加不同前缀或检索策略。

### 5.11 `ingest_service.py`：文档入库编排

这是文档上传后的业务入口。

负责按顺序调用：

```text
空间校验
→ 文件保存
→ documents(processing)
→ 文档解析
→ 文本切片
→ BGE-M3 编码
→ chunks 批量写入
→ documents(ready)
```

失败处理：

- 捕获可预期的解析、模型和数据库错误。
- 回滚本次切片写入。
- 将文档标为 `failed` 并记录简短错误。
- 不把密钥、完整调用栈返回给浏览器。

公开函数：

```python
ingest_document(file, space_id) -> DocumentResult
```

### 5.12 `retrieve.py`：隔离向量检索

负责：

- 接收问题向量和服务端算出的 `allowed_spaces`。
- 在 SQL 的 `WHERE` 中先过滤空间和 `ready` 文档。
- 使用 cosine 距离排序。
- 返回最多 `top_k` 个片段及其真实文档信息。

公开函数：

```python
search_chunks(query_vector, allowed_spaces, top_k) -> list[RetrievedChunk]
```

关键 SQL 语义：

```sql
SELECT ...
FROM chunks
JOIN documents ON documents.id = chunks.document_id
WHERE chunks.space_id = ANY(:allowed_spaces)
  AND documents.status = 'ready'
ORDER BY chunks.embedding <=> :query_vector
LIMIT :top_k;
```

禁止在没有空间条件的情况下执行向量排序。

### 5.13 `generate.py`：答案生成

负责：

- 创建 DeepSeek 客户端。
- 将问题和召回片段组装为 Prompt。
- 调用 `deepseek-chat`。
- 返回纯答案文本。

Prompt 规则：

- 只根据提供的片段回答。
- 片段不足或相互冲突时说明无法确认。
- 不编造制度、代码步骤、成绩结论或来源。
- 回答尽量简洁。

不负责：

- 检索、命中阈值判断、角色判断。
- 生成来源链接。来源由 `qa_service.py` 从召回结果整理。

公开函数：

```python
generate_answer(question, chunks) -> str
```

### 5.14 `qa_service.py`：问答编排

这是问答业务的唯一入口。

流程：

```text
角色 → 允许空间
→ 问题向量
→ 隔离检索
→ 命中判断
   ├─ 未命中：固定拒答，不调用 DeepSeek
   └─ 命中：调用 DeepSeek → 整理来源 → 返回
```

负责：

- 校验问题。
- 调用 `roles.py` 获取允许空间。
- 调用 BGE-M3 和检索模块。
- 用最高相似度判断是否命中。
- 去重来源，最多返回 3 个。
- 未命中时返回固定文案和空来源。

公开函数：

```python
answer_question(role, question) -> AskResult
```

### 5.15 `routes/documents.py`：文档接口

负责：

- 接收 multipart 文件和空间参数。
- 做 HTTP 级参数校验。
- 调用 `ingest_service.py`。
- 将业务结果转换为 HTTP 响应。

推荐状态码：

- `201`：入库成功。
- `400`：空间、格式、空文件不合法。
- `413`：超过大小限制。
- `500`：无法完成入库。

### 5.16 `routes/ask.py`：问答接口

负责：

- 接收 `AskRequest`。
- 调用 `qa_service.py`。
- 返回统一的 `AskResponse`。

不接受 `space_ids` 参数，防止客户端绕过角色映射。

### 5.17 `routes/health.py`：健康检查

负责：

- 检查 API 是否运行。
- 检查数据库是否可连接。
- 显示 BGE-M3 是否加载完成。

不调用 DeepSeek，以免健康检查产生费用或因外网波动误判本地服务故障。

### 5.18 `frontend/`：产品前端

Vue 3 单页应用，只消费 V1 API。身份以 `GET /me` 为准；会话 Cookie 名仍为 `fde_session`。构建产物在 `frontend/dist`，由 `backend/spa.py` 挂载。不再提供 Streamlit 或内置 HTML 演示壳。

## 6. 核心时序

### 6.1 文档入库

```text
浏览器
  → documents 路由
  → ingest_service
  → storage 保存文件
  → documents 写 processing
  → parsers 提取文本
  → chunker 切片
  → embed 批量编码
  → chunks 批量写入
  → documents 改 ready
  → 返回文档结果
```

### 6.2 命中问答

```text
浏览器
  → ask 路由
  → qa_service
  → roles 得到允许空间
  → embed 生成问题向量
  → retrieve 按空间检索
  → qa_service 判断命中
  → generate 调用 DeepSeek
  → qa_service 整理真实来源
  → 返回答案
```

### 6.3 未命中问答

```text
浏览器
  → ask 路由
  → qa_service
  → roles / embed / retrieve
  → 相似度低于阈值
  → 返回固定拒答、hit=false、sources=[]
```

未命中流程不调用 DeepSeek。

## 7. 接口定义

### 7.1 上传文档

```text
POST /documents
Content-Type: multipart/form-data

space=student
file=<课程说明.md>
```

响应示例：

```json
{
  "id": "document-uuid",
  "title": "课程说明.md",
  "space_id": "student",
  "status": "ready",
  "chunk_count": 8
}
```

### 7.2 提问

```json
POST /ask
{
  "role": "student",
  "question": "课程作业应该如何提交？"
}
```

命中响应：

```json
{
  "answer": "……",
  "hit": true,
  "sources": [
    {
      "document_id": "document-uuid",
      "title": "课程说明.md",
      "space_id": "student"
    }
  ]
}
```

未命中响应：

```json
{
  "answer": "知识库中没有足够依据回答这个问题。",
  "hit": false,
  "sources": []
}
```

## 8. 异常处理

| 场景 | 系统行为 |
| --- | --- |
| 不支持的文件格式 | 返回 400，不保存文档记录 |
| 文件过大 | 返回 413 |
| PDF 是扫描件 | 文档标记 failed，提示暂不支持 OCR |
| BGE-M3 未加载 | 健康检查失败；入库和问答返回 503 |
| 数据库不可用 | 返回 503 |
| DeepSeek 超时或失败 | 返回 502，不伪装成知识库未命中 |
| 无检索结果 | 返回正常 200，`hit=false` |
| 非法角色 | 返回 400 |

“知识库未命中”和“系统故障”必须区分，不能都显示为“没有答案”。

## 9. 测试划分

### 单元测试

- `roles.py`：三种角色映射和非法角色。
- `chunker.py`：长度、重叠、空文本。
- `parsers.py`：三种格式和空文件。
- `qa_service.py`：命中调用 DeepSeek；未命中不调用。

### 集成测试

- 入库后数据库存在正确空间的切片。
- `student` 检索 SQL 不返回 `company` 切片。
- `employee` 只能返回 `company`。
- `teaching` 可以返回两个空间。
- 来源 ID 和标题来自数据库，而不是模型文本。

### 演示验收

- 上传一篇课程文档（学伴样例）和一篇内部制度/FAQ 样例（智能助手样例）。
- 三种模拟身份分别提问。
- 展示学员无法命中内部文档。
- 展示知识库无答案时固定拒答。

## 10. MVP 之后如何扩展

扩展时保留入库、向量、检索和生成模块，不重写 AI 主链路，不复制第二套 FastAPI 服务。

```text
┌─────────────────────────────────────────────────────────┐
│ 入口：Vue 产品前端（同源托管）/ 可选 Gradio      │
└───────────────────────────┬─────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────┐
│ 共享内核（MVP 已有，V1 只换授权来源）                    │
│  ingest → embed → retrieve(allowed_spaces) → generate   │
│  来源由召回记录生成；未命中不调 LLM                      │
└───┬─────────────────────────┬───────────────────────────┘
    │ V1                      │ V2 插件（按空间启用）
    ▼                         ▼
  auth / members           学伴：path / OCR
  tickets / owners         助手：onboarding（Skill 另开）
```

### 10.1 V1：真实产品能力

新增模块：

| 模块 | 功能 | 对现有模块的影响 |
| --- | --- | --- |
| `auth` | 登录、密码、Token | 路由从登录态获取用户 |
| `users` | 用户、角色、教学岗标记 | 替代模拟 `role` |
| `space_members` | 真实空间成员关系 | 替换 `roles.py` 的固定映射 |
| `document_admin` | 更新、下线、解析状态 | 复用入库模块 |
| `conversations` | 会话与消息历史 | 问答前加载上下文 |
| `student_tickets` | 学员未命中转班主任 | 接在 `hit=false` 后 |
| `topic_owners` | 内部问题负责人联系方式 | 接在员工 `hit=false` 后 |

关键扩展点：

```text
MVP：role 参数 → roles.py → allowed_spaces
V1：登录用户 → space_members → allowed_spaces
```

`retrieve.py` 始终只接收服务端算出的 `allowed_spaces`，空间隔离规则不变。

### 10.2 V2：场景插件（学伴 + 智能助手）

插件只消费内核已经算出的 `allowed_spaces` 与召回结果，禁止自己做全库检索。

| 模块 | 场景 | 功能 | 对现有模块的影响 |
| --- | --- | --- | --- |
| `code_ingest` | 共用 | 仓库文件切片（路径、语言） | 复用 `ingest_service` / `embed` / `chunks.space_id` |
| `advanced_resources` | 学伴 | 薄弱点 → 相关性闭环检索 + 推荐文章 | 课内来自召回；课外 URL 来自搜索且过白名单；`ref_id` 不可编造 |
| `ocr_ingest` | 学伴 | 截图/公式 OCR 后走 `/ask` | OCR 失败 ≠ 知识库未命中 |
| `onboarding` | 助手 | 入职类问句时检索 query 拼岗位中文名 | 仍走 `/ask`；无独立页 |
| `skills` | 助手 | 公司 Skill | **本仓库本阶段不做**；另开需求 |

V2 不增加代码执行沙箱容器。作业批改暂不实现。出网仅白名单：进阶资料课外搜索（arXiv + Tavily，结果过主机白名单）。

流式输出（SSE）只包装问答接口，不改变命中判断。Gradio 只做场景演示壳，权限仍走 FastAPI。

助手与学伴专项执行版：`docs/V2-B需求分析.md`、`docs/V2-A需求分析.md`。

### 10.3 明确不在扩展中做的拆分

- 不为学伴和智能助手各建一套 pgvector 或各建一个 API 进程（可用 Compose profile 区分入口，不是两套内核）。
- 不为 V2 预建空的 `agents/` 包；有第一个工具再加文件。
- 不实现代码执行沙箱或 `POST /debug`。
- 混合检索、rerank：已实现，见 `docs/混合检索与重排设计.md`。
- HNSW 仅在评测证明需要时再加。

## 11. 架构约束

开发中必须遵守：

1. 空间过滤必须写入向量检索 SQL。
2. 客户端不能直接决定可检索空间。
3. 未命中不调用 DeepSeek。
4. 来源由数据库召回记录生成。
5. BGE-M3 只加载一次。
6. 失败文档不参与检索。
7. MVP 不新增用户、工单、Redis、Celery、沙箱、OCR 等非当前范围模块。
8. 优先写可替换的小函数，不引入通用框架抽象。
9. V1/V2 新增能力不得绕过 `allowed_spaces`；不得把两场景拆成两套检索实现。
