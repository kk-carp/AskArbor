# 产品化前端需求分析


| 项    | 内容                                                                                           |
| ---- | -------------------------------------------------------------------------------------------- |
| 定位   | V1 之后的产品入口补完（V1.1），与 V2-A 学伴插件并行，互不阻塞                                                        |
| 对应基线 | `docs/需求分析.md` 主入口「自建 Web + API」；V1 已交付登录/文档/问答/工单/负责人接口                                     |
| 对应选型 | 本文拍板 Vue 3；实现前同步 `docs/技术选型.md`                                                              |
| 前置   | V1 API 可用：`/login` `/ask` `/documents` `/conversations` `/tickets` `/topic_owners` `/health` |
| 范围   | 用 Vue 3 覆盖 V1 全部用户可见流程，作为可交付产品的主界面                                                           |
| 不在范围 | 重写 RAG、第二套鉴权业务、SSE、Gradio、学伴沙箱/OCR 的后端                                                       |


本文说明 **产品化前端做什么、不做什么、如何验收**。实施任务另拆，本文不写组件清单级实现步骤。

---

## 1. 背景与目标

### 1.1 结论

V1 后端已经是可登录、可授权、可运维文档、可转人工的最小产品。产品入口为 Vue 3，只消费同一套 FastAPI。

本专项把 **同一套 FastAPI** 配上独立 Vue 3 前端，不增加业务语义，不把 `allowed_spaces` 或命中判断搬到浏览器。

V2-A（代码入库、沙箱、批改、路径、OCR）仍按 `docs/V2-A需求分析.md` 做后端；学伴能力就绪后，在本前端加入口即可，不要求本专项先做学伴页。

### 1.2 相对现状


| 项                   | 现在                                           | 本专项之后                                                                         |
| ------------------- | -------------------------------------------- | ----------------------------------------------------------------------------- |
| 产品入口                | 已删除的 Streamlit / 内置 HTML                     | Vue 3 单页应用为默认入口                                                               |
| 鉴权                  | Session Cookie                                 | 浏览器同源访问 API，Cookie 随请求发送                                                      |
| 问答                  | 刷新后易只剩对话文本，命中/工单/负责人提示弱                      | 明确展示 `hit`、来源、`ticket_id`、`owner`                                             |
| 权限展示                | 各页自行判断                                       | 按 `/me` 的 `role` / `is_teaching` / `can_manage_documents` 显示菜单，**真正拒绝仍在 API** |
| Streamlit / 内置 HTML | 已删除                                          | 仅 Vue 产品入口                                                                    |




### 1.3 硬约束

1. 前端不得传 `role` / `space_ids` 改变检索或工具范围。
2. 不得在浏览器里二次过滤来源来「假装」空间隔离；学员看不到 `company` 必须来自服务端响应。
3. 不得实现第二套登录表、工单表或本地伪造 `/me`。
4. `hit=false`、502、503、工具失败的文案必须区分，与 V1/V2-A 错误语义一致。
5. 不把对话写入知识库；不展示参考答案全文（A3 之后同样遵守）。
6. 生产环境前端与 API **同源**（由 FastAPI 托管构建产物，或反向代理同一域名），避免跨站 Cookie 问题。

## 2. 范围与非目标



### 2.1 范围内（第一期 = 覆盖 V1）

登录后按角色看到不同菜单，页面只调已有接口。


| 页面      | 谁用                     | 调用                                                                  | 必须做到                            |
| ------- | ---------------------- | ------------------------------------------------------------------- | ------------------------------- |
| 登录 / 退出 | 全员                     | `POST /login` `POST /logout` `GET /me`                              | 未登录进业务页跳转登录；401 清会话             |
| 问答      | 已登录                    | `POST /ask` `GET /conversations` `GET /conversations/{id}/messages` | 会话列表、新会话、追问；展示答案、来源、`hit`       |
| 文档管理    | `can_manage_documents` | `GET/POST /documents` `POST /documents/{id}/offline`                | 上传、状态/失败原因、下线；无权限不显示入口（进了也 403） |
| 工单      | 学员 / 处理人 / 教学岗         | `GET/POST /tickets` `POST /tickets/{id}/reply`                      | 学员可见自动单与显式建单；处理人可回复             |
| 主题负责人   | 教学岗                    | `GET/PUT /topic_owners`                                             | 配置关键词与联系方式；普通员工无入口              |


问答页额外产品要求（补上当前演示缺口）：

- `hit=true` 与 `hit=false` 在刷新后仍能从当次结果或会话旁路看清，不能只剩模型「依据不足」而当成未命中。
- 学员 `hit=false` 且返回 `ticket_id` 时，明确「已建工单」并提供去工单页的入口。
- 员工 `hit=false` 时展示 `owner`：已配置则显示姓名与联系方式；`configured=false` 则显示「未配置」。学员响应中的 `owner` 为 `null`，界面不出现内部负责人。
- 来源只渲染接口里的 `sources`（title、space_id、document_id，以及将来的 path），不解析模型正文里的书名号当来源。
- 401/400（如未绑定班主任）/502/503 用错误区展示，不当成拒答。



### 2.2 范围内（第二期，不阻塞第一期验收）

V2-A 接口落地后，在同一 Vue 应用加学伴入口（调试、批改、学习路径、OCR、代码包上传）。权限与空间裁剪仍以后端为准（学伴上下文仅 `student`）。

本专项第一期 **不实现** 这些页面的业务，只要求信息架构预留菜单位置即可（也可第一期完全不出现学伴菜单）。

### 2.3 明确不做

- Next.js / Gradio 作为产品主入口。
- SSE 流式问答（基线 V2-A6 延后）。
- 前端计算允许空间、命中阈值、工单处理人。
- 开放注册、SSO、飞书为唯一入口。
- 独立 BFF 或第二套后端。
- 移动端原生 App；第一期以桌面浏览器为主。



### 2.4 已拍板

1. 技术栈：**Vue 3** + Vite + **Element Plus** + Pinia + vue-router 4。
2. 与 API 关系：只做展示与路由；业务规则以 FastAPI 为准。
3. 鉴权：**继续用现有 Session Cookie**，不在本专项改 JWT（若以后要改，前后端同一迭代切换）。
4. 交付形态：构建产物由 FastAPI 静态托管，用户只访问一个 origin（例如 `http://127.0.0.1:8000`）。



### 2.5 仍待确认（不阻塞页面）

1. 暗色主题、中英文。第一期仅中文浅色。

## 4. 信息架构与权限（展示层）

菜单只根据 `/me` 显示隐藏，防止学员误点；**隐藏不等于安全**，接口仍要 401/403。


| 菜单    | 学员  | 员工                     | 教学岗 |
| ----- | --- | ---------------------- | --- |
| 问答    | 是   | 是                      | 是   |
| 工单    | 是   | 仅当有指派或自己提交（列表由 API 过滤） | 是   |
| 文档管理  | 否   | 否                      | 是   |
| 主题负责人 | 否   | 否                      | 是   |
| 退出    | 是   | 是                      | 是   |


顶栏固定展示：用户名、角色、`allowed_spaces`（只读）。不提供「切换空间再提问」控件。

## 5. 关键交互



### 5.1 登录

```text
打开站点 → GET /me
  ├─ 200：进入默认页（问答）
  └─ 401：登录表单
登录成功 → 写 Cookie（浏览器自动）→ 拉 /me → 按权限渲染菜单
任意业务接口 401 → 清本地用户态 → 回登录页
```



### 5.2 问答（含未命中分流展示）

```text
选会话或新开会话 → 输入问题 → POST /ask（可选 conversation_id）
  ├─ 200 hit=true：答案 + 来源列表
  ├─ 200 hit=false：固定拒答文案 + 无来源
  │     ├─ 学员且 ticket_id：提示已建单，链到工单
  │     └─ 员工且 owner：配置则展示联系人，否则「未配置」
  ├─ 400：展示 detail（如未绑定班主任）
  ├─ 502：上游失败，提示稍后重试，不说「知识库没有」
  └─ 503：服务未就绪
```

会话消息列表来自 `GET .../messages`，与当次 `/ask` 的 `hit` / `ticket_id` / `owner` 一并保存到前端会话态或随消息元数据展示，避免一刷新只剩纯文本。

第一期后端若仍不落库 `hit` 字段，前端须在当次响应中缓存这些字段；不得把助手消息里出现「依据不足」自动当成 `hit=false`。

### 5.3 文档 / 工单 / 负责人

与现有产品行为对齐：上传选 `student` 或 `company`（仅教学岗）；下线需确认；工单回复不提示「已入库」；负责人联系方式只用表单提交值，不调模型生成。

## 6. 与后端的衔接



### 6.1 本专项需要后端改动的部分

以 **尽量零改业务** 为原则。为同源托管，FastAPI 增加：挂载 Vue `dist`、除 `/api` 已有路由外将前端路由回退到 `index.html`（具体挂载路径实现时定）。

开发 proxy 时，Cookie 路径与 `session_cookie_name`（`fde_session`）保持不变。

**不必须** 为了前端而改成 JWT。若开发不用 proxy、直连跨端口，才需要 CORS `allow_credentials` 与 Cookie 属性调整——优先用 proxy 避免这条。

### 6.2 接口清单（第一期只消费，不新增业务接口）

`POST /login`、`POST /logout`、`GET /me`、`POST /ask`、`GET /conversations`、`GET /conversations/{id}/messages`、`GET|POST /documents`、`POST /documents/{id}/offline`、`GET|POST /tickets`、`POST /tickets/{id}/reply`、`GET|PUT /topic_owners`、`GET /health`。

Ask 响应字段以现网为准：`answer`、`hit`、`sources`、`conversation_id`、`ticket_id`、`owner`。

## 7. 验收标准

1. 未登录访问问答/文档/工单，进入登录或收到 401 处理后跳转登录。
2. `student_demo` 问答页看不到「切换为 company」之类控件；伪造请求体 `space_ids` 仍检不到内部文档（与 V1 一致，前端不协助伪造）。
3. 教学岗能完成：登录 → 上传 → 列表看到状态 → 下线。
4. 学员未命中（真 `hit=false`）能看到工单号或工单页有对应记录；员工未命中能看到负责人或「未配置」。
5. `hit=true` 但模型写「依据不足」时，界面仍显示「命中知识库」并列出 `sources`，不自动建单提示。
6. 502 文案不是「知识库没有」；503 不是未命中。
7. 生产/Compose 场景：只起 API（及 DB），浏览器打开同一端口即可用 Vue。
8. 学员界面不出现内部空间标题、路径或文档 ID（依赖 API；前端不把其他用户问到的 company 来源写进本地缓存展示给学员）。

## 8. 现状差距


| 项              | 状态                           |
| -------------- | ---------------------------- |
| Vue 工程         | `frontend/`（Vue 3 + Vite + Element Plus） |
| FastAPI 托管 SPA | `backend/spa.py`：存在 `frontend/dist` 时挂载，否则 `/` 返回 503 |
| V1 API         | **已有**，本专项以消费为主              |
| Streamlit / 内置 HTML | 已删除 |


建议落地顺序：工程脚手架与同源托管 → 登录 + `/me` → 问答（命中/未命中/工单/负责人展示）→ 文档管理 → 工单 → 主题负责人 → README 切换主入口。
