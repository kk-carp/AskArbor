# 统一知识助手技术选型


| 项     | 结论                                                             |
| ----- | -------------------------------------------------------------- |
| 项目性质  | FDE 课程实践项目；学伴与智能助手共用一套内核                                       |
| 当前阶段  | MVP：只验证 AI 知识问答主链路与双空间隔离                                       |
| 后端    | Python 3.11+、FastAPI、Uvicorn                                   |
| 向量模型  | 本地 `BAAI/bge-m3`，仅使用 1024 维 dense 向量                           |
| 大语言模型 | DeepSeek `deepseek-chat`，通过 OpenAI 兼容接口调用                      |
| 数据库   | PostgreSQL 16 + pgvector，使用 Docker 启动                          |
| 文档格式  | Markdown / TXT、PDF、DOCX                                        |
| 前端    | Vue 3（`frontend/`，Element Plus）；由 FastAPI 同源托管 `frontend/dist` |


设计原则：先用最少组件完成「文档入库 → 隔离检索 → 生成答案 → 展示来源」。登录、工单、OCR、代码仓索引在 MVP 验证完成后再建设。代码执行沙箱不在产品范围。两场景不选两套技术栈。

---

## 1. MVP 要实现什么

MVP 只实现 AI 相关能力：

1. 将文档上传到 `student` 或 `company` 知识空间。
2. 解析文档、切片，并用 BGE-M3 生成向量。
3. 根据模拟身份限制检索空间。
4. 从 pgvector 检索相关片段。
5. 有可靠片段时调用 DeepSeek 生成答案，并返回文档来源。
6. 没有可靠片段时明确拒答，不编造答案或来源。

```text
文档上传
   ↓
解析与切片
   ↓
BGE-M3 向量化
   ↓
PostgreSQL + pgvector
   ↓
按身份限制空间并检索
   ↓
命中 → DeepSeek 作答 + 来源
未命中 → 固定拒答
```



### 身份与空间映射

MVP 不做真实账号，使用请求中的 `role` 模拟身份。空间列表由服务端映射，客户端不能直接指定。


| 模拟身份       | 可检索空间               |
| ---------- | ------------------- |
| `student`  | `student`           |
| `employee` | `company`           |
| `teaching` | `student`、`company` |


隔离必须发生在数据库检索阶段：

```sql
WHERE space_id = ANY(:allowed_spaces)
```

禁止先检索全部向量，再在 Python 中过滤无权限结果。

## 2. MVP 技术架构

MVP 只有两个运行组件：

```text
浏览器
   │ HTTP
   ▼
FastAPI
├── 简单 HTML 页面
├── 文档解析与切片
├── BGE-M3（进程内加载）
├── 空间过滤与向量检索
└── DeepSeek 客户端
   │
   ▼
PostgreSQL + pgvector（Docker）
```



### 组件职责


| 组件                    | 职责                     |
| --------------------- | ---------------------- |
| FastAPI               | 上传文档、执行入库、接收问题、返回答案和来源 |
| BGE-M3                | 为文档切片和用户问题生成向量         |
| PostgreSQL + pgvector | 保存空间、文档、切片和向量；执行隔离检索   |
| DeepSeek              | 根据检索片段生成最终答案           |
| 简单 HTML               | 选择模拟身份、上传文档、提交问题、展示结果  |


MVP 不引入 Redis、Celery、Nginx、对象存储或独立前端服务。

## 3. 具体技术选型



### 3.1 FastAPI

选择 FastAPI，因为项目以 Python AI 链路为主，接口少，开发和演示成本低。

MVP 接口：

- `POST /documents`：上传文档，参数 `space=student|company`
- `POST /ask`：提交 `{ "role": "...", "question": "..." }`
- `GET /`：返回简单演示页面
- `GET /health`：检查 API 和数据库状态

不使用 Django、NestJS，也不拆分微服务。

### 3.2 BGE-M3

- 模型：`BAAI/bge-m3`
- 加载：使用 `sentence-transformers`
- 输出：只使用 1024 维 dense 向量
- 运行位置：FastAPI 进程内，启动时加载一次
- 设备：自动使用 CUDA；没有 GPU 时使用 CPU
- 批大小：默认 8

MVP 不使用 BGE-M3 的 sparse、ColBERT 和 rerank 能力。

首次运行需要下载模型权重。国内下载受阻时可配置：

```text
HF_ENDPOINT=https://hf-mirror.com
```



### 3.3 DeepSeek

- 模型：`deepseek-chat`
- SDK：官方 `openai` Python SDK
- 地址：`https://api.deepseek.com`
- 用途：只负责根据检索片段组织答案

系统提示必须约束模型：

- 只能依据提供的文档片段回答。
- 依据不足时说明知识库没有相关内容。
- 不得编造制度、步骤或来源。
- 来源由服务端根据实际召回文档生成，不让模型虚构链接。



### 3.4 PostgreSQL + pgvector

- PostgreSQL 16
- Docker 镜像：`pgvector/pgvector:pg16`
- 向量类型：`vector(1024)`
- 距离：cosine，使用 `<=>`
- 默认召回数量：`top_k=5`

MVP 数据量小，不创建 HNSW 或 IVFFlat 向量索引，直接顺序扫描即可。

### 3.5 文档解析与切片


| 格式             | 处理方式              |
| -------------- | ----------------- |
| Markdown / TXT | Python 直接读取 UTF-8 |
| PDF            | `pypdf`           |
| DOCX           | `python-docx`     |


切片采用简单字符窗口：

- 每片约 800 个字符
- 相邻片段重叠 100 个字符
- 保存文档 ID、空间 ID、片段序号和正文

MVP 不做 OCR、表格结构还原、智能章节切片或复杂文档预处理。

## 4. 数据模型

MVP 只需要三张表。

### `spaces`

- `id`：`student` 或 `company`
- `name`



### `documents`

- `id`
- `space_id`
- `title`
- `file_path`
- `status`：`processing` / `ready` / `failed`
- `error`
- `created_at`



### `chunks`

- `id`
- `document_id`
- `space_id`
- `chunk_index`
- `content`
- `embedding vector(1024)`

`chunks.space_id` 有意冗余，用于确保向量检索能直接按空间过滤。

MVP 不创建用户、会话、消息、工单和负责人表。

---



## 5. 核心处理流程



### 5.1 文档入库

1. 校验空间和文件类型。
2. 将文件保存到本地上传目录。
3. 新建 `documents` 记录，状态为 `processing`。
4. 解析文本并切片。
5. 用 BGE-M3 批量生成向量。
6. 将切片与向量写入 `chunks`。
7. 文档状态改为 `ready`。

任一步失败则状态改为 `failed`，失败文档不得参与检索。

入库在上传请求中同步执行。课程样例文件较小，不引入异步任务队列。

### 5.2 问答

1. 服务端根据 `role` 得到允许的空间。
2. 用 BGE-M3 为问题生成向量。
3. 在允许空间内检索最相关的 5 个片段。
4. 无结果或最高分低于阈值时直接拒答，不调用 DeepSeek。
5. 命中时将问题和检索片段发送给 DeepSeek。
6. 返回答案，以及服务端整理的真实文档来源。

建议响应：

```json
{
  "answer": "……",
  "hit": true,
  "sources": [
    { "document_id": "……", "title": "课程说明.md" }
  ]
}
```

初始相似度阈值设为 `0.3`，但它不是最终业务值。必须使用样例问题分别观察命中和未命中的分数后调整。

## 6. 项目结构

```text
backend/
  main.py
  config.py
  db.py
  models.py
  roles.py
  embed.py
  ingest.py
  retrieve.py
  generate.py
  spa.py
data/uploads/
docker-compose.yml
requirements.txt
.env.example
```

模块职责：

- `roles.py`：模拟身份到空间的固定映射
- `embed.py`：加载 BGE-M3，并提供统一编码函数
- `ingest.py`：解析、切片、向量化和入库
- `retrieve.py`：带空间过滤的 pgvector 检索
- `generate.py`：调用 DeepSeek 生成答案

不使用 LangChain 或 LlamaIndex。当前链路很短，直接实现更容易验证空间隔离、阈值拒答和来源真实性。

## 8. MVP 验收标准

1. 上传课程文档到 `student` 后，`student` 能获得带来源的答案。
2. 上传内部文档到 `company` 后，`employee` 能获得带来源的答案。
3. `student` 询问内部文档内容时，不返回该文档的标题、片段或来源。
4. `teaching` 能检索两个空间。
5. 询问知识库没有的内容时返回 `hit=false`，且不调用 DeepSeek。
6. 检索代码或 SQL 能明确看到空间条件先于向量排序。

## 9. MVP 之后的扩展选型

扩展按价值增加，不在 MVP 中预建空表、空模块或新依赖。内核选型（FastAPI、BGE-M3、pgvector、DeepSeek）保持不变。

### 9.1 V1：可供真实用户使用


| 能力        | 选型                                                                                                                                                                  | 不选                                              |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| 鉴权        | 服务端 Session 或 JWT，用户在 PostgreSQL                                                                                                                                    | 把 `role` 继续交给客户端                                |
| 成员        | `space_members` 计算 `allowed_spaces`                                                                                                                                 | 每场景一套权限服务                                       |
| 后台 / 产品界面 | **产品入口**为 Vue 3 + Vite + Element Plus + Pinia + vue-router 4，Session Cookie，开发期 Vite 把 API 路径 proxy 到 `:8000`，生产由 FastAPI 托管 `frontend/dist`（见 `docs/产品化前端需求分析.md`） | 把鉴权或空间计算放到前端；另起 BFF；Next.js；Streamlit / 内置 HTML |
| 部署        | Docker Compose：API + Postgres                                                                                                                                       | 微服务、K8s                                         |
| 转人工       | 学员工单表；内部负责人表                                                                                                                                                        | 未命中与 502 混用文案                                   |


关键变化：`role` 不再来自请求参数，而是由登录用户的空间成员关系生成 `allowed_spaces`。检索函数仍只接收服务端计算出的空间列表。

产品前端不新增业务语义：不传 `role` / `space_ids`，不在浏览器二次过滤来源。页面路径避开与 GET API 冲突（问答 `/qa`、文档 `/knowledge`、工单 `/work-orders`、负责人 `/topic-owners`）。

### 9.2 V2：场景插件（学伴 + 智能助手）

两场景共用同一 LLM 与向量库，按空间启用工具。


| 能力           | 选型                                                                                                                                            | 说明                                                                                                        |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 流式对话         | FastAPI SSE 包装现有 `/ask`                                                                                                                       | 命中判断仍在流开始前完成                                                                                              |
| 学伴界面 / 内部工具页 | 可选 Gradio，调用同一 API                                                                                                                            | 不替代鉴权，不做第二套业务                                                                                             |
| OCR          | Qwen-VL（DashScope OpenAI 兼容，`VISION_*`）优先抽文本；PaddleOCR 可选兜底（`OCR_ENABLED`，未安装则跳过） | 失败与未命中分错误语义；禁止看图直接答题绕过 RAG |
| 学习路径         | 提问记录 → `student` 检索课内；服务端搜索课外（arXiv + Tavily，结果过主机白名单/收费课黑名单） | 禁止模型编造 URL；不推荐收费课/训练营/对标课程；搜索失败 ≠ `hit=false`；课外不入库 |
| 入职推荐         | 入职类问句时检索 query 拼接岗位中文名（`position_key`）                                                                                                                     | 仍走 `/ask`；无独立页、无四类强制清单                                                                                        |
| 公司 Skill     | **本仓库本阶段不做**                                                                                      | 对接公司既有 Skill 库等另开专项；未拍板前不加依赖与路由                                                                        |
| 代码 + 文档混合索引  | 仍 BGE-M3 dense；切片带 `path`/`language`                                                                                                          | 先不引入第二套 embedding                                                                                         |
| 观测           | 结构化日志：延迟、命中、工具失败、解决率                                                                                                                          | MVP 不做看板；V2 再接简易指标                                                                                        |


Agent / 工具：本仓库 V2 现阶段仅入库检索、OCR、学习路径搜索、入职推荐检索等已拍板能力。不引入 LangChain/LlamaIndex 作为内核。禁止任意 Shell、未登记出网、空 `agents/` 包。不做代码执行沙箱与 `POST /debug`。作业批改暂不实现。**公司 Skill 路由本阶段不做。**

V2-A4 课外搜索已拍板：`httpx` 请求 `https://export.arxiv.org/api/query`（论文，无 key）与 `https://api.tavily.com/search`（网页，需 `TAVILY_API_KEY`，超时 15 秒，禁止跟随重定向）；Tavily 请求带 `include_domains`（展示白名单）与 `exclude_domains`（收费课黑名单）；展示链接仍须再过 `filter_search_hits`。不引入 `tavily` SDK。无 key 时 Tavily 记为 `search_unavailable`，arXiv 仍可返回。

V2-B5（arXiv Skill）已移出本专项；原「开工前抄入选型」要求作废。学习路径 arXiv 主机约定仍见 V2-A。




### 9.3 仍按评测再决定

- HNSW / IVFFlat：文档与代码规模变大、顺序扫描变慢后再加。
- 混合检索 / rerank：有评测集证明 dense 不够再用。
- 对象存储、Celery：入库与截图量成为瓶颈后再加。
- 飞书/微信适配器：不作为主入口。

---



## 10. MVP 明确不做

- LangChain、LlamaIndex、Dify、RAGFlow、FastGPT
- 独立 Next.js 前端、Gradio（V2 可选）
- JWT、用户表、权限管理
- Redis、Celery、对象存储
- HNSW / IVFFlat、混合检索、rerank
- 多轮记忆、SSE 流式输出
- 班主任工单和内部负责人匹配
- 代码沙箱、OCR、tree-sitter、Git API
- 为两个业务场景拆两套服务
- 生产部署

上述能力不是被否定，而是与当前课程 MVP 的验收无关；需要时按第 9 节逐步扩展。
