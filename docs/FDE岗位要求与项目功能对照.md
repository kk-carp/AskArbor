# FDE 岗位要求 × 本项目功能对照

> 给学员用：左侧是招聘里常写的能力，右侧是本仓库里能对着讲、对着跑的功能。  
> 能力来源见 [AI应用开发与FDE学习路径与实践资料推荐.md](./AI应用开发与FDE学习路径与实践资料推荐.md)；课表对照见 [01-课程覆盖.md](./01-课程覆盖.md)。

**一句话**：本仓是「可演示的生产级 RAG + 轻量 Agent」实践课，对应 FDE 硬门槛里的 RAG / Eval / 权限 / Agent / CE；行业 ROI、驻场、以及「自己写一个 MCP 工具服务并接到 Cursor 等」需课外补。

## 0. 先分清两个词：MCP Client / MCP Server

招聘和文档里常写 **MCP**，本仓只做其中一半，容易误解。用插座类比：

| 角色 | 是什么 | 本仓有没有 | 学员要知道什么 |
| --- | --- | --- | --- |
| **MCP Client（客户端）** | **去调用**工具的一方：Agent / 本仓后端按协议向工具发请求 | ✅ 有 | 课上练的是「统一调度现有搜索/工具」，见 `15-MCP-Client` |
| **MCP Server（服务端）** | **对外提供**工具的一方：别人连上你，就能用你暴露的能力（如搜文档、查库） | ⏭ 课内不做产品化 | JD 常要求「自己写过 Server」——需**课外**另做一个小项目 |

**「多客户端对接」是什么意思？**  
指同一个 MCP Server 能被 **多个不同的客户端**连上使用，例如同时被 Cursor、Claude Desktop、Claude Code 调用。招聘里常见写法是：「写一个 MCP Server，能接 3 个以上客户端」。

**「需课外」是什么意思？**  
= **本仓库课程作业/产品范围里不做**，若简历要对齐 JD，请自己另开小仓库练；不是「上课讲不清」或「永远不用学」。

```text
本仓（Client）：我们的 Agent ──调用──▶ 已有工具（搜索等）
课外可补（Server）：Cursor / Claude ──调用──▶ 你写的 MCP Server（你提供的工具）
```

| 岗位要求（JD 常见表述）         | 本仓对应                                                                | 标记  | 面试可说                                  | 去哪看                              |
| --------------------- | ------------------------------------------------------------------- | --- | ------------------------------------- | -------------------------------- |

| 未命中 / 幻觉控制            | 低于阈值固定拒答；来源来自库召回，不让模型编                                              | ✅   | 「502 和知识库未命中语义分开」                     | `qa_service` / `retrieve`        |
| Agent（工具 + 编排）        | 进阶资料推荐：薄弱点 → 检索/搜索 → 推荐；含压缩、Memory、长任务                              | ✅   | 「垂直场景 Agent，不是通用助手；有失败降级」             | `06`；`08`；`13`                   |
| Context Engineering   | 会话压缩、跨会话 Memory、本仓 Skill、长任务续跑                                      | ✅   | 「上下文当预算管：摘要、外置笔记、按需加载」                | `07`；`08`；`12`；`14`              |
| MCP                   | 只做 **Client**：用协议统一调度本仓工具（off/shadow/merge）；**不**对外提供 Server | 🟡  | 「课上会调工具协议；自己写 Server 并接到 Cursor 等是课外补的」 | `15`；上文 §0；`08` |
| Python / 后端工程         | FastAPI + PostgreSQL/pgvector + Vue；分层 routes/services/domain/infra | ✅   | 「单体可测、可部署；选型自研不套 Dify」                | `03`；`04`                        |
| Token / 时延意识          | 评测记延迟与 usage；拒答 token=0；流式 `/ask/stream`                            | ✅   | 「能报 P 分位延迟和单次成本量级」                    | `02`；课 27                        |
| 提示词工程化                | JSON schema 输出 + 校验失败重试 + 仍失败降级                                     | ✅   | 「结构化输出当血管，失败有兜底」                      | 课 26；`weak_points`               |
| 多模态进 RAG              | 截图 OCR → 再走 `/ask`                                                  | ✅   | 「图先变文字再进既有链路，不另起一套」                   | 课 31                             |
| 可观测 / Trace 看板        | 进程内指标、request_id、评测报表；无完整 Langfuse 类面板                              | 🟡  | 「有评测与基础指标；完整 Trace 面板可课外接」            | `09-上线差距`                        |
| 上线真实用户                | 课程演示 / 内网试用级；非长期生产基线                                                | 🟡  | 「内核可演示验收；上线差距见 09」                    | `09`                             |
| 自建 MCP Server + 多客户端对接 | 明确不做（见 §0） | ⏭ | 课外写一个小 Server，用 Cursor/Claude Desktop 等至少 2～3 个客户端连上验证 | 学习路径阶段 4；§0 |
| 微调 LoRA               | 不做                                                                  | ⏭   | 「优先 Eval 与检索，不为用技术而微调」                | `01`                             |
| 行业 know-how / ROI 一页纸 | 产品场景是学伴+助手，无完整 ROI 报告                                               | ⏭   | 用本仓场景自己写一页纸 ROI                       | 学习路径阶段 6                         |
| 出差/驻场意愿               | 非技术项                                                                | ⏭   | 诚实自评即可                                | —                                |

| 能力                  | 本仓                | 说明               |

## 5. 面试：用本仓回答高频题


| 面试官常问          | 用本仓怎么答（要点）                            |
| -------------- | ------------------------------------- |
| RAG 效果差怎么查？    | 先跑评测集 → 看召回/重排分数 → 再动切分或阈值；隔离问题用越权样本  |
| Agent 好不好怎么衡量？ | 任务是否完成、工具是否选对、是否乱调模型；本仓用推荐结果 + 降级路径说明 |
| 上下文爆了怎么办？      | 滚动摘要压缩；重要进度外置（长任务/Memory）；工具返回要短      |
| 模型答错线上怎么办？     | 低分拒答；未命中分流（工单/负责人）；502≠没知识            |
| MCP 怎么设计？      | 先讲本仓 Client：统一映射 + off/shadow/merge；再说明 JD 要的「自建 Server + 多客户端」是课外另做的（见 §0） |
| 一年能省多少钱？       | 本仓无现成 ROI——用「答疑人天 / 入职摸索时间」自己算一页纸     |
| 为什么不用微调？       | 课标与选型：先检索与 Eval；知识更新靠入库比改权重更合适        |


更全的自检清单见学习路径文档「四、面试准备」。

## 6. 本仓刻意不做（避免学偏）


| 不做                               | 原因（与岗位对照）              |
| -------------------------------- | ---------------------- |
| LangChain / LangGraph / Dify 进内核 | 练自研链路；框架可课外读           |
| Gradio / Streamlit               | 产品入口是 Vue              |
| LoRA / 语音                        | JD 里微调多为加分；Eval 才是硬门槛  |
| 对外提供 MCP Server、公司 SkillHub | 课内只做「调用方」Client + 本仓 Skill；不把本仓做成可被 Cursor 连接的工具服务 |
| 第二套实验内核                          | 所有能力挂在同一 RAG 链路上       |

## 7. 建议学习顺序（对着本仓）

```text
1. 跑通问答主链（入库 → 隔离检索 → 拒答/带来源）
2. 跑评测作业，记下延迟、token、隔离结果
3. 跟一遍进阶资料 Agent + 压缩 / Memory / 长任务
4. 读 MCP Client 三模式；若要对齐 JD，课外自写一个 Server 并用 Cursor 等客户端连上（见 §0）
5. 读 09 上线差距，区分「课上能讲」和「真上线还差什么」
6. 选一个行业，用本仓场景写一页 ROI（补 FDE 非技术项）
```
