# 项目结构映射（旧路径 -> 新路径）

本映射用于把当前实现对齐到 `routes / services / domain / infra` 四层结构，保持行为不变、便于后续 V1/V2 迭代。

## 应用层映射

| 旧路径 | 新路径 | 说明 |
| --- | --- | --- |
| `app/auth.py` | `app/services/auth_service.py` | 登录、会话、用户加载；旧文件保留兼容导出 |
| `app/ingest_service.py` | `app/services/ingest_service.py` | 入库编排服务；旧文件保留兼容导出 |
| `app/qa_service.py` | `app/services/qa_service.py` | 问答编排服务；旧文件保留兼容导出 |
| `app/membership.py` | `app/domain/membership.py` | 成员关系与 `allowed_spaces` 规则 |
| `app/roles.py` | `app/domain/roles_compat.py` | 兼容旧 role 映射入口，逐步退场 |
| `app/chunker.py` | `app/infra/chunker.py` | 切片能力 |
| `app/parsers.py` | `app/infra/parsers.py` | 文档解析能力 |
| `app/storage.py` | `app/infra/storage.py` | 文件落盘能力 |
| `app/embed.py` | `app/infra/embed.py` | 向量模型加载与编码能力 |
| `app/retrieve.py` | `app/infra/retrieve.py` | pgvector 隔离检索能力 |
| `app/generate.py` | `app/infra/generate.py` | DeepSeek 生成能力 |
| `app/seed.py` | `app/seed/demo_users.py` | 演示账号种子 |
| （V1 新增） | `app/services/ticket_service.py`、`app/services/topic_owner_service.py` | 学员工单与内部负责人 |

## 路由依赖调整

- `app/routes/ask.py`：改为依赖 `app/services/auth_service.py` 提供登录态上下文，并调用 `app/services/qa_service.py`。
- `app/routes/auth.py`：改为依赖 `app/services/auth_service.py`，避免路由内重复登录态解析逻辑。
- `app/routes/documents.py`：改为依赖 `app/services/ingest_service.py`。

## 兼容策略

- 保留原顶层模块（如 `app/qa_service.py`）作为兼容导出，降低一次性迁移风险。
- 新代码优先从 `services/domain/infra/seed` 目录导入；旧导入路径仅用于过渡。

## `allowed_spaces` 统一入口与 `roles` 退场路径

- 当前唯一授权查询入口：`app/domain/membership.py#get_allowed_spaces_for_user`。
- 路由统一通过 `app/services/auth_service.py#load_auth_context` 获取登录用户与 `allowed_spaces`，避免在多个路由重复拼授权逻辑。
- `app/domain/roles_compat.py` 仅保留给旧测试与兼容调用。
- 退场顺序建议：
  1. 业务代码停止引用 `app/roles.py`；
  2. 将 `tests/unit/test_roles.py` 标记为兼容测试；
  3. V1 授权稳定后删除 `app/roles.py` 与 `app/domain/roles_compat.py`。
