# 统一知识助手 项目需求分析


| 项        | 内容                                                                      |
| -------- | ----------------------------------------------------------------------- |
| 项目       | 统一知识助手（学伴 + 智能助手）                                                       |
| 课程定位     | **FDE 课程实践项目**。先交付可演示的 AI 内核，再按场景补完整产品能力                                |
| 文档性质     | 需求基准（V6）。完整产品决策仍有效；**当前开发范围以第 4 节 MVP 为准**；V2 学伴/助手以第 8 节为准 |
| 产品形态     | **一套内核、两个场景**：按身份分权限，同一套 RAG 服务课程问答与内部研发问答                              |
| MVP 范围   | **只做 AI 相关实现**：解析切片、向量检索、按空间隔离、LLM 作答带来源、未命中拒答                          |
| 主入口（MVP） | 最简 Web 问答（可选身份/空间）+ API。完整登录/后台/工单/Agent 不在 MVP                         |
| 知识源（MVP） | 自建双空间知识库；第一批由管理员手动上传                                                    |
| 回答策略     | 命中则直接回答并附来源；答不了则承认没有（转人工、学习路径、入职推荐等见 V1/V2）                               |
| 实现路径     | **方案 B：自研** FastAPI + pgvector + LLM。不套 Dify / RAGFlow / FastGPT / Aily |
| 场景合并决策   | 学伴与智能助手**不拆成两套系统**；共享入库、检索、生成与隔离，场景能力以插件接在内核之后                          |


---

## 1. 背景与问题

这是 **FDE 课程的实践项目**，同时对应公司两条真实业务线：


| 场景   | 用户         | 核心痛点                                                |
| ---- | ---------- | --------------------------------------------------- |
| 学伴   | 学员、讲师、助教   | 前沿科技课程密度高、代码实操多；助教答疑慢且覆盖不全；环境报错多；知识点更新快、关联复杂，学员容易迷失 |
| 智能助手 | 算法研发、大模型研发、新入职员工 | 资料分散；新人不知先读哪份指南、哪段代码、哪份技术文档、先做哪些任务；岗位技能（写文章、查论文等）未接到同一助手 |


两条线看起来像两个产品，但主链路相同：

```text
知识进入自建库 → 按身份只检索允许空间 → 有依据则作答并带来源 → 无依据则明确说没有
```

差异在「知识类型」和「命中之后还能做什么」：学伴要接学习路径、OCR（作业批改暂不实现）；智能助手要接入职推荐，并白名单接入公司 Skill（如技术文章生成、arXiv 论文下载）。这些能力都挂在同一内核上，**不复制两套 RAG**。

课程上要遵守的是：

- 时间有限，**MVP 先把 AI 链路做通**（入库 → 隔离检索 → 生成），用它证明双场景隔离和引用来源。
- 账号、工单、负责人、OCR、代码仓库索引属于完整产品，不阻塞 MVP。代码调试助手与隔离沙箱不在产品范围。

## 2. 目标与非目标



### 2.1 目标（分三层）

**MVP（当前要做，已作为开发范围）**

- 文档进入自建库后，能按指定空间检索，并用 LLM 生成带依据的答案。
- 强制按 `space_id` 隔离：课程空间的提问不得命中内部研发切片。
- 依据不足时明确说没有，不编造来源。
- 用最少界面或 API 演示：选身份 → 提问 → 看到答案和来源。
- 用虚构课程样例代表学伴场景，用虚构内部制度/研发 FAQ 样例代表智能助手场景。

**V1（MVP 之后的最小可上线产品）**

- Web 登录后按真实账号身份问答，不再信任客户端 `role`。
- 管理员维护两个空间的文档：状态可见、失败原因可见、下线后不可检索。
- 未命中分流：学员走班主任工单；内部员工展示问题负责人联系方式。
- 教学岗 / 双场景人员同时拥有两个空间成员。
- 保持 RAG 主链路不重写，只替换「允许空间」的计算来源。

**V2（场景能力，按插件接到 V1 之后）**

学伴：

1. 课程知识库问答扩展到讲义/课件/课程代码仓库。
2. 学习路径推荐：根据提问历史识别薄弱点；推荐课程空间已入库资料，并搜索开源/免费课外阅读与论文（不推荐收费课、训练营、对标本公司产品的课程）。
3. 多模态：上传代码截图/公式图，OCR 后进入既有问答流程。
4. 作业智能批改：**暂不实现**（需求保留，不进入当前 V2-A 工期）。

智能助手：

1. 新人入职推荐：按岗位推荐入职指南、相应代码库、职位相关技术文档和任务；条目必须来自 `company` 召回，禁止编造。
2. 公司 Skill 插件：在同一助手里白名单接入岗位技能，第一期示例为技术文章生成、arXiv 论文下载；默认不自动入库。
3. 内部知识问答仍走既有 `/ask`（Wiki / 制度 / FAQ 已入库即可问）。



### 2.2 非目标

**MVP 不做**

- 完整账号密码、角色管理、班主任绑定、教学岗开关。
- 学员工单流转、班主任回复后台。
- 员工主题负责人配置与匹配（MVP 未命中只说「知识库没有」）。
- 代码执行沙箱、作业批改、学习路径、OCR、代码仓库索引、Git/CI 调用。
- 精致知识后台、Gradio 学伴界面、流式对话。
- 生产级 HTTPS/域名、限流与审计看板。

**完整产品也不做（V1/V2 仍排除）**

- 打卡、考试系统、操作带练、完整 HR 入职系统（本系统只做基于知识库的入职资料与任务**推荐**）。
- 对话自动入库；无人确认写知识库。
- 改成绩、代写作业、输出内部未授权代码。
- 代码调试助手、隔离执行沙箱（学员粘贴代码在服务端运行）。
- 用 Aily 或开源知识库套件替换自研问答内核。
- 全功能 Wiki 协同编辑。
- 飞书/微信作为**唯一**主入口（可作为 V2 适配器，不替代自建 Web/API）。
- 把学伴与智能助手拆成两套独立后端、两套向量库。

| 决策点               | 结论                                      | 何时落地                                                                                   |
| ----------------- | --------------------------------------- | -------------------------------------------------------------------------------------- |
| 课程性质              | FDE 实践项目，MVP 先做 AI 内核                   | 现在                                                                                     |
| 产品形态              | 统一助手，一套内核两个场景，按身份分权限                    | 检索设计现在就要按此做                                                                            |
| 是否拆系统             | **不合则重复建设；现阶不合到两套服务**。场景差异用空间 + 插件表达    | 现在拍板，V2 仍遵守                                                                            |
| 知识拆分              | `student` = 学伴课程空间；`company` = 智能助手内部空间 | **MVP 必须**                                                                             |

| 知识写入              | 管理员手动上传；对话不自动入库                         | MVP 用脚本/简易上传                                                                           |

| 转人工               | 学员→班主任工单；内部员工→负责人联系方式                   | **V1**；MVP 只拒答                                                                         |
| 主入口               | 自建 Web + API                            | MVP 曾用最简聊天页；V1 曾用登录页/Streamlit；**当前产品入口为 Vue 3**（`docs/产品化前端需求分析.md`）；V2 可加 Gradio 场景页 |
| 实现路径              | 自研 FastAPI + pgvector + OpenAI 兼容 LLM   | MVP                                                                                    |
| Agent / OCR / 代码库 | 接在命中判断之后，不改变隔离检索                        | **V2**                                                                                 |

## 4. MVP：AI 相关实现（当前开发范围）

只要求这条链路可演示，不要求真用户体系，也不实现学伴/智能助手的 Agent 能力。

```text
手动放入目录或简易上传的文档（标明 student 或 company）
        │
        ▼
解析（Markdown / PDF / docx）→ 切片 → Embedding → 写入 pgvector（每条带 space_id）
        │
提问（请求携带身份：学员 / 内部员工 / 教学岗）
        │
        ▼
只在允许空间内向量检索
        │
        ├── 分数够 → LLM 只根据片段作答 + 文档标题/来源
        └── 不够 / 无片段 → 「知识库没有」，不编造，不建工单
```



### 4.1 MVP 必须交付

1. **入库**：指定空间，解析 MD/PDF/docx，切片，向量化，写入库。
2. **隔离检索**：查询带 `space_id IN (...)`；无权限切片不得进入候选。
3. **生成**：OpenAI 兼容 LLM；提示词要求只根据片段回答；列出 1～3 个真实来源。
4. **拒答**：低于阈值或无召回时承认没有。
5. **身份模拟**（用于验收隔离，不是完整账号）：请求参数 `role=student|employee|teaching` 映射到空间列表。问答接口不接受客户端 `space_ids`。
6. **演示入口**：问答 API 必做；有最简网页更好。
7. **护栏（轻量）**：系统提示拒绝代写作业、编造制度、输出无依据内容。

身份与空间对应（MVP 写死映射即可）：


| 模拟身份           | 业务含义             | 允许检索的空间               |
| -------------- | ---------------- | --------------------- |
| 学员 `student`   | 学伴学员             | 仅 `student`           |
| 员工 `employee`  | 智能助手侧内部人员（非教学岗）  | 仅 `company`           |
| 教学岗 `teaching` | 讲师/助教，或同时做课与研发的人 | `student` + `company` |




### 4.2 MVP 明确不做

登录注册、班主任、工单、主题负责人表、完整管理后台、必须持久化的多轮会话、生产部署、代码沙箱、OCR、作业批改、学习路径、代码仓库解析、GitLab API。

多轮追问为加分，不是必须。

### 4.3 MVP 验收

- 向 `student` 空间放入课程类文档后，以学员身份能问到，答案带来源。
- 向 `company` 空间放入一篇内部制度/研发 FAQ 样例后，学员身份提问不得出现该文档标题、片段或来源。
- 员工身份能问到公司样例；教学岗身份两空间文档都能问到。
- 问库中没有的内容：承认没有，不捏造链接。
- 隔离发生在检索层，不是「搜完全量再把内部结果丢掉」。



### 4.4 MVP 推荐实现栈（可瘦身）


| 层         | MVP                            | V1 再补                               | V2 再补                      |
| --------- | ------------------------------ | ----------------------------------- | -------------------------- |
| API       | FastAPI：上传或目录入库、问答             | 鉴权、工单、负责人匹配                         | 流式对话、入职推荐、Skill 接口          |
| 数据        | PostgreSQL + pgvector：空间、文档、切片 | 用户、成员、工单、主题负责人                      | 岗位画像（可选）、推荐条目仍来自文档切片            |
| 文件        | 本地磁盘                           | 同左或对象存储                             | 截图、代码仓快照                   |
| Embedding | BGE-M3 dense                   | 同左                                  | 代码切片策略可独立，模型可先不换           |
| LLM       | OpenAI 兼容接口（DeepSeek）          | 同左                                  | Agent 工具调用仍走同一 LLM         |
| 界面        | 最简聊天页（可选身份）                    | **Vue 3 产品入口**（`docs/产品化前端需求分析.md`） | Gradio 学伴页仍为可选；学伴能力进同一 Vue |
| 运行        | 本地启动 API + Postgres            | Docker Compose 整包                   | 内网可关外网工具           |


MVP 在仓库根目录实现 FastAPI 单体（入库 + 检索 + 问答）。产品入口见 `docs/产品化前端需求分析.md`（Vue 3）。

## 5. 完整产品：双场景与角色（V1 起）

空间语义固定，角色由管理员赋予。用户不能自报身份升级。未分配角色不检索。


| 角色         | 主场景  | 做什么                 | 能检索什么                 | 看不到什么            |
| ---------- | ---- | ------------------- | --------------------- | ---------------- |
| 学员         | 学伴   | 登录后问课程、实验、作业规范、报错   | 仅 `student`           | 智能助手内部资料、后台、他人作业 |
| 讲师 / 助教    | 学伴   | 维护课程文档、处理学员工单       | 默认 `student`          | 无成员关系的内部研发文档     |
| 班主任        | 学伴   | 处理所带学员工单            | 默认 `student`          | 非所带学员工单          |
| 算法 / 大模型研发 | 智能助手 | 问内部资料、拿入职推荐、调用已开通 Skill | 仅 `company`           | 学员空间正文、学员工单      |
| 教学岗员工      | 两场景  | 同时问课程资料与内部知识        | `student` + `company` | 未授权仓库/文档         |
| 主题负责人      | 智能助手 | 文档上登记联系方式，不强制在系统里回复 | `company`             | 无成员关系的学员文档       |
| 管理员        | 共用   | 账号、空间、上传、配置         | 按配置                   | —                |
| 助手         | 共用   | 按身份检索并作答或转人工        | 当前允许的空间               | 不得把内部片段写入学员会话    |


V2 在上述角色上叠加能力，不新开第二套权限模型：学员才能用学习路径/OCR；内部员工才能用入职推荐与公司 Skill；隔离规则不变。作业批改暂不实现。

## 6. 身份与知识隔离

三层都要有，V1 做全；**MVP 必须做到第 1 层和第 3 层**，第 2 层用身份参数模拟。

1. **存放**：课程与内部资料分属两个空间。禁止同一文档记录挂两个空间。两边都要用的内容，复制成两份分别入库。V2 的代码仓、Wiki、Issue 同样写入所属空间，不建「全局代码索引」。
2. **成员（V1）**：`space_members` 决定谁能进哪个空间。学员只有 `student`；普通内部员工只有 `company`；**教学岗必须同时加入两者**。学员账号绑定班主任。
3. **检索（MVP 就必须）**：查询强制 `space_id IN (:allowed)`。学员会话不得返回内部空间的标题、片段、来源或代码。

V1 判定顺序：

1. 教学岗员工 → `company` + `student`
2. 普通内部员工 → 只 `company`
3. 班主任 / 老师 / 助教 → `student`；若同时是教学岗再叠加 `company`
4. 学员 → 只 `student`，并绑定班主任
5. 无角色 → 不检索

V2 工具与 Skill（OCR、入职推荐检索、文章生成、arXiv 下载）必须在已算出的 `allowed_spaces` 之内执行。禁止工具先读全库再过滤。客户端不得指定可检索空间或未注册的 Skill 名。

## 7. V1 功能需求（产品化，不含场景 Agent）

下列条目在 MVP **不必实现**。实现时仍按此做，且不改 RAG 主链路。

### 7.1 账号与登录

- 邮箱/账号 + 密码。管理员创建并指定角色。
- 学员必须绑定班主任。
- 员工可标教学岗：标记后自动加入两空间；取消则退出 `student`。
- 无游客问答。



### 7.2 问答（相对 MVP 的增量）

- 登录态提问；支持同一会话追问。
- 未命中走第 7.4 节转人工，而不是只说没有。
- 护栏与 MVP 相同，可继续加强。



### 7.3 知识后台

- 管理员手动上传 MD/PDF/docx。
- 内部文档可填负责人姓名 + 联系方式。
- 解析状态、失败原因、更新换版本、下线后不可检索。
- 不做在线富文本编辑器。



### 7.4 转人工

**学员（学伴）：** 未命中或点转人工 → 工单，默认处理人 = 班主任。班主任后台回复。回复不入库。

**内部员工（智能助手）：** 不默认建工单。展示该问题对应负责人的姓名与联系方式。匹配顺序：主题负责人表 → 弱相关文档上的负责人 → 未配置则说明未配置，禁止编造。

系统故障（502/503）不得走转人工文案，也不得伪装成知识库未命中。

### 7.5 日志与审计

记录用户、角色、空间、是否命中、引用文档 ID。学员界面不得出现内部空间正文。

## 8. V2 场景能力（学伴 + 智能助手）

V2 只增加「命中之后 / 未命中之后」的能力，**不新开第二套检索内核**。每个能力必须带空间约束，并单独验收。学伴专项见 `docs/V2-A需求分析.md`；智能助手专项见 `docs/V2-B需求分析.md`。

### 8.1 学伴

**8.1.1 课程知识库问答（在 MVP RAG 上扩展知识源）**

- 来源：讲义、课件、课程代码仓库（按文件切片，带路径与符号名）。
- 仍只在 `student`（及教学岗允许的空间）内检索。
- 回答「某算法原理」「某段代码含义」必须带来源路径或文档标题。

**8.1.2 作业智能批改（暂不实现）**

- 对比参考答案与学员提交，输出正确性判断 + 改进建议（代码类作业）。
- 不改成绩、不替学员交作业。参考答案只对讲师/助教可见完整正文。
- **当前 V2-A 不排期、不建表、不提供接口。** 恢复时单独立项，不得顺手改 RAG 主链路。

**8.1.3 学习路径推荐**

- 根据该学员近期提问历史识别薄弱点（第一期不用测验）。
- **课内：** 推荐课程空间已入库资料；每条必须能在 `student` 对应到 `document_id` 或 `path`，禁止编造。
- **课外：** 调用服务端搜索函数，推荐开源、免费的阅读资料与论文；链接必须来自搜索结果。尽量不推荐收费课程、训练营，以及对标本公司产品的课程。
- 课内空、课外空、搜索失败与 `/ask` 未命中分语义；搜索失败不得建学员工单，也不得丢掉已有课内列表。
- 课外结果不入库。执行细节与白名单见 `docs/V2-A需求分析.md`。

**8.1.4 多模态**

- 上传代码截图 / 公式图 → OCR → 进入既有问答流程。
- OCR 失败与知识库未命中使用不同错误语义。



### 8.2 智能助手

**8.2.1 新人入职推荐（第一期）**

- 登录员工（须有 `company` 成员）按**岗位**得到推荐清单，至少四类：入职指南、相应代码库、职位相关技术文档、任务。
- 每条推荐必须能在 `company` 空间对应到真实 `document_id` 或仓库相对路径（或管理员登记的代码仓标识）；禁止编造外链、内部仓路径或任务标题。
- 无依据则空列表 + 说明「没有可推荐资料」，不调用「知识库未命中建工单」（工单仅学员）。
- 学员调用返回 403。教学岗以智能助手身份使用时，推荐检索仍只使用 `company`，不得把 `student` 课程资料塞进新员工清单。
- 不做打卡、考试、操作带练、自动派工到外部任务系统。

**8.2.2 公司 Skill 插件（第一期示例）**

- 在同一套助手中白名单接入公司已有能力（Skill）。客户端只能点名已注册 Skill，不能传入任意 URL/Shell。
- 第一期示例：
  - **技术文章生成：** 根据用户说明与 `company` 召回草稿；默认不入库，人审确认后才可走既有入库。
  - **arXiv 论文下载：** 仅允许访问 arXiv 官方接口/PDF；失败用独立 `error_type`（如 `skill_failed` / `arxiv_failed`），不得写成 `hit=false`，不得建学员工单。
- 后续 Skill 按同样约束追加，不新开第二套后端。未拍板的 Skill 不得写入 `requirements.txt`。
- Skill 知识上下文默认只使用 `company`；禁止把学员空间或未授权仓送进 Prompt / 下载工作区。

**8.2.3 内部知识问答（沿用 `/ask`）**

- Wiki、制度、FAQ、已入库技术文档仍走既有检索与拒答。来源必须是召回记录。
- 不在助手侧另做一套 FAQ 引擎。

**8.2.4 本阶段不做（原智能助手清单，延后）**

- tree-sitter 符号级代码解释、实验配置助手、自动代码审查合入、任意 Git 写操作。需要时另开任务，不阻塞入职推荐与 Skill 第一期。



### 8.3 V2 共用约束

- Agent / Skill 白名单：检索、入职推荐、已注册公司 Skill（第一期：文章生成、arXiv 下载）、OCR。禁止任意 Shell、任意出网。不做代码执行沙箱。
- 工具入参不得由客户端指定 `space_ids`。
- 效果指标：学伴侧重答疑解决率；智能助手侧重新人「能否拿到真实指南/仓/文档/任务」与 Skill 成功率。需求回流进知识库须人工确认。

## 9. 数据模型

**MVP 最小表：** `spaces`、`documents`、`chunks`（含向量与 `space_id`）。

**V1 再加：**

- `users`：角色、教学岗、学员的班主任
- `space_members`
- `topic_owners`：分类 → 负责人联系方式
- `conversations` / `messages`
- `tickets`：仅学员工单

**V2 再加（有能力再建模，不预建空表）：**

- `knowledge_points` / `learner_signals`：知识点与薄弱记录（学伴；第一期可用会话代替）
- `chunks.path` / `language`（两场景代码与文档来源；A1 已有）
- 岗位标签或画像（智能助手入职推荐依据；无调用方不建表）
- `assignments` / `submissions`：作业与提交（学伴批改恢复时再建模）

检索硬约束始终不变：只在允许的 `space_id` 里取 Top-K，禁止先搜全集再过滤。

入库流水线（各阶段相同内核）：选空间 → 解析 → 切片 → 向量 → 写入；失败则该文档不可检索。

## 11. 验收标准

**MVP（课程实践当前关卡）**

- 手动入库的课程文档，学员身份能问到并带来源。
- 内部样例文档，学员身份问不到任何内部正文或标题。
- 员工 / 教学岗身份的检索范围符合第 4.1 节映射。
- 库中没有的问题被明确拒绝，不编造来源。

**V1（产品关卡）**

- 真实登录；教学岗写入成员表后两空间可检。
- 学员未命中生成班主任工单；内部员工未命中展示负责人联系方式或「未配置」。
- 伪造内部 `space_id` 的学员 token 检不到内部切片。
- 对话不写入知识库。失败文档下线后不可检索。

**V2 学伴**

- 课程代码/讲义可问到，来源含文档或仓库路径。
- 学习路径：课内条目能在 `student` 对应到文档或 path；课外条目来自搜索且为开源/免费阅读或论文；不出现收费课、训练营、编造链接。
- 截图 OCR 后能走通问答或给出 OCR 失败。
- 作业批改本阶段不验收。

**V2 智能助手**

- 新员工能拿到分类推荐（指南 / 代码库 / 技术文档 / 任务），每条有真实来源；无资料则空列表说明。
- 已开通 Skill（文章生成、arXiv 下载）可调用；失败语义不是知识库未命中。
- 生成草稿默认不入库。学员身份拿不到内部推荐与内部 Skill 结果。

## 12. 范围

**MVP（现在写代码的范围）：** 双空间入库 + 隔离向量检索 + LLM 带依据作答 + 未命中拒答 + 身份模拟演示。

**V1：** 登录、管理员上传后台、教学岗成员、班主任工单、内部负责人联系方式、会话、Docker Compose 整包。

**产品化前端（V1.1）：** Vue 3 作为可交付主入口，只消费 V1 API。Streamlit 与内置 HTML 演示壳已删除。见 `docs/产品化前端需求分析.md`。

**V2：** 学伴（代码仓 RAG、学习路径、OCR；作业批改暂不实现）+ 智能助手（入职推荐、公司 Skill、既有 `/ask`）+ 可选 Gradio 场景界面与流式输出。学伴见 `docs/V2-A需求分析.md`；助手见 `docs/V2-B需求分析.md`。

**明确延后或不做：** 打卡/考试/操作带练、对话自动入库、SSO/飞书作唯一入口、把两场景拆成微服务、代码调试助手与隔离执行沙箱、作业批改（暂缓）。
