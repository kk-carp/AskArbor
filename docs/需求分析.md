# 统一知识助手 项目需求分析

| 项 | 内容 |
| --- | --- |
| 项目 | 统一知识助手（学员答疑 + 新员工培训） |
| 课程定位 | **FDE 课程实践项目**。先交付可演示的 AI 内核，再补完整产品能力 |
| 文档性质 | 需求基准（V4）。完整产品决策仍有效；**当前开发范围以第 4 节 MVP 为准** |
| 产品形态 | 一个助手，按身份分权限：学员只问课程知识，员工只问（或优先问）公司内部知识 |
| MVP 范围 | **只做 AI 相关实现**：解析切片、向量检索、按空间隔离、LLM 作答带来源、未命中拒答 |
| 主入口（MVP） | 最简 Web 问答（可选身份/空间）+ API。完整登录/后台/工单不在 MVP |
| 知识源 | 自建双空间知识库；第一批由管理员手动上传（MVP 可用脚本或简易上传接口） |
| 回答策略 | 命中则直接回答并附来源；答不了则承认没有（班主任工单、负责人联系方式见 V1） |
| 实现路径 | **方案 B：自研** FastAPI + pgvector + LLM。不套 Dify / RAGFlow / FastGPT / Aily |

---

## 1. 背景与问题

这是 **FDE 课程的实践项目**：在「学员答疑 + 新员工培训」这个真实形态下，做出一套可演示的知识问答。

业务上要解决的是：

- 同一套 AI 既回答课程/实验/报错，也回答公司流程/规范。
- 两套资料隔离，学员不得看到内部文档。
- 不绑飞书，自建知识库，检索和权限自己控。

课程上要遵守的是：

- 时间有限，**MVP 先把 AI 链路做通**（入库 → 检索 → 生成），用它证明隔离和引用来源。
- 账号、班主任工单、主题负责人、精致后台属于完整产品（V1），不阻塞 MVP。

---

## 2. 目标与非目标

### 2.1 目标（分两层）

**MVP（当前要做）**

- 文档进入自建库后，能按指定空间检索，并用 LLM 生成带依据的答案。
- 强制按 `space_id` 隔离：学员空间的提问不得命中公司切片。
- 依据不足时明确说没有，不编造来源。
- 用最少界面或 API 演示：选身份（或空间）→ 提问 → 看到答案和来源。

**完整产品 V1（MVP 之后）**

- Web 登录后按真实账号身份问答。
- 管理员手动上传维护两个空间。
- 未命中：学员工单给班主任；员工展示问题负责人联系方式。
- 教学岗员工同时拥有两个空间成员。

### 2.2 非目标

**MVP 不做**

- 完整账号密码、角色管理、班主任绑定、教学岗开关。
- 学员工单流转、班主任回复后台。
- 员工主题负责人配置与匹配（MVP 未命中只说「知识库没有」）。
- 精致知识后台、运营向的下线/版本可视化。
- 生产级 Docker、HTTPS/域名、限流与审计看板。

**完整产品也不做**

- 入职路径、打卡、考试、操作带练。
- 对话自动入库；无人确认写知识库。
- 检索代码仓库；识别截图。
- 飞书机器人 / 微信 / App 作主入口。
- 用 Aily 或开源知识库套件当问答内核。
- 全功能 Wiki 协同编辑。
- 改成绩、代写作业等越权请求（护栏直接拒；MVP 用提示词即可）。

| 决策点 | 结论 | 何时落地 |
| --- | --- | --- |
| 课程性质 | FDE 实践项目，MVP 先做 AI | 现在 |

| 实现路径 | 自研 FastAPI + pgvector + OpenAI 兼容 LLM | MVP |

## 4. MVP：AI 相关实现（当前开发范围）

只要求这条链路可演示，不要求真用户体系。

```text
手动放入目录或简易上传的文档（标明 student 或 company）
        │
        ▼
解析（Markdown / PDF / docx）→ 切片 → Embedding → 写入 pgvector（每条带 space_id）
        │
提问（请求携带身份：学员 / 员工 / 教学岗）
        │
        ▼
只在允许空间内向量检索
        │
        ├── 分数够 → LLM 只根据片段作答 + 文档标题/来源
        └── 不够 / 无片段 → 「知识库没有」，不编造，不建工单
```

### 4.1 MVP 必须交付

1. **入库**：指定空间，解析 MD/PDF/docx，切片，向量化，写入库。
2. **隔离检索**：查询带 `space_id IN (...)`；无权限切片不得进入候选。
3. **生成**：OpenAI 兼容 LLM；提示词要求只根据片段回答；列出 1～3 个真实来源。
4. **拒答**：低于阈值或无召回时承认没有。
5. **身份模拟**（用于验收隔离，不是完整账号），三选一即可：
   - 请求参数 `role=student|employee|teaching` 映射到空间列表；或
   - 页面上的身份下拉框；或
   - 直接传 `space_ids`（若采用此项，文档须写明 V1 改为服务端按账号授权）。
6. **演示入口**：问答 API 必做；有最简网页更好。
7. **护栏（轻量）**：系统提示拒绝代写作业、编造制度、输出无依据内容。

身份与空间对应（MVP 写死映射即可）：

| 模拟身份 | 允许检索的空间 |
| --- | --- |
| 学员 `student` | 仅 `student` |
| 员工 `employee` | 仅 `company` |
| 教学岗 `teaching` | `student` + `company` |

### 4.2 MVP 明确不做

登录注册、班主任、工单、主题负责人表、完整管理后台、必须持久化的多轮会话、生产部署。

多轮追问为加分，不是必须。

### 4.3 MVP 验收

- 向 `student` 空间放入 FDE/课程类文档后，以学员身份能问到，答案带来源。
- 向 `company` 空间放入一篇内部制度样例后，学员身份提问不得出现该文档标题、片段或来源。
- 员工身份能问到公司样例；教学岗身份两空间文档都能问到。
- 问库中没有的内容：承认没有，不捏造链接。
- 隔离发生在检索层，不是「搜完全量再把公司结果丢掉」。

### 4.4 MVP 推荐实现栈（可瘦身）

| 层 | MVP | V1 再补 |
| --- | --- | --- |
| API | FastAPI：上传或目录入库、问答 | 鉴权、工单、负责人匹配 |
| 数据 | PostgreSQL + pgvector：空间、文档、切片 | 用户、成员、工单、主题负责人 |
| 文件 | 本地磁盘 | 对象存储 |
| Embedding | 中文优先（如 bge-m3 或兼容 OpenAI 的接口） | 同左 |
| LLM | OpenAI 兼容接口 | 同左 |
| 界面 | 最简聊天页（可选身份） | Next.js 登录/后台/工单 |
| 运行 | 本地启动 API + Postgres 即可 | Docker Compose 整包 |

MVP 在仓库根目录实现 FastAPI 单体（入库 + 检索 + 问答），演示页由同一应用提供，不拆独立前端。

## 5. 完整产品：用户与主场景（V1）

| 角色 | 做什么 | 能检索什么 | 看不到什么 |
| --- | --- | --- | --- |
| 学员 | 登录后问课程、环境、作业规范、报错 | 仅 `student` | 公司内部资料；后台 |
| 新员工（非教学岗） | 问业务流程、岗位规范、内部 FAQ | 仅 `company` | 学员空间正文 |
| 教学岗员工 | 同时问内部知识与课程资料 | `company` 和 `student` | 未授权内容 |
| 班主任 | 处理所带学员工单 | 默认 `student` | 非所带学员工单 |
| 老师 / 助教 | 维护 `student` 文档 | `student` | 无成员关系的公司文档 |
| 业务负责人 | 文档上登记联系方式，不强制在系统里回复 | `company` | 无成员关系的学员文档 |
| 管理员 | 账号、空间、上传、配置 | 按配置 | — |
| 助手 | 按身份检索并作答或转人工 | 当前允许的空间 | 不得把内部片段写入学员会话 |

角色只由管理员赋予。用户不能自报「我是员工」升级。未分配角色不检索。

## 6. 身份与知识隔离

三层都要有，V1 做全；**MVP 必须做到第 1 层和第 3 层**，第 2 层用身份参数模拟。

1. **存放**：课程与内部资料分属两个空间。禁止同一文档记录挂两个空间。两边都要用的内容，复制成两份分别入库。
2. **成员（V1）**：`space_members` 决定谁能进哪个空间。学员只有 `student`；普通员工只有 `company`；**教学岗员工必须同时加入两者**。学员账号绑定班主任。
3. **检索（MVP 就必须）**：查询强制 `space_id IN (:allowed)`。学员会话不得返回公司空间的标题、片段或来源。

V1 判定顺序：

1. 教学岗员工 → `company` + `student`
2. 普通员工 → 只 `company`
3. 班主任 / 老师 → `student`；若同时是教学岗再叠加 `company`
4. 学员 → 只 `student`，并绑定班主任
5. 无角色 → 不检索

## 7. 完整产品功能需求（V1）

下列条目在 MVP **不必实现**，避免和 AI 内核抢时间。实现时仍按此做。

### 7.1 账号与登录

- 邮箱/账号 + 密码。管理员创建并指定角色。
- 学员必须绑定班主任。
- 员工可标教学岗：标记后自动加入两空间；取消则退出 `student`。
- 无游客问答。

### 7.2 问答（相对 MVP 的增量）

- 登录态提问；支持同一会话追问。
- 未命中走第 7.4 节转人工，而不是只说没有。
- 护栏与 MVP 相同，可继续加强。

### 7.3 知识后台

- 管理员手动上传 MD/PDF/docx（第一批即如此）。
- 公司文档可填负责人姓名 + 联系方式。
- 解析状态、更新换版本、下线后不可检索。
- 不做在线富文本编辑器。

### 7.4 转人工

**学员：** 未命中或点转人工 → 工单，默认处理人 = 班主任。班主任后台回复。回复不入库。

**员工：** 不默认建工单。展示该问题对应负责人的姓名与联系方式。匹配顺序：主题负责人表 → 弱相关文档上的负责人 → 未配置则说明未配置，禁止编造。

### 7.5 日志与审计

记录用户、角色、空间、是否命中、引用文档 ID。学员界面不得出现公司空间正文。

## 8. V1 数据模型（MVP 只用子集）

**MVP 最小表：** `spaces`、`documents`、`chunks`（含向量与 `space_id`）。

**V1 再加：**

- `users`：角色、教学岗、学员的班主任
- `space_members`
- `topic_owners`：分类 → 负责人联系方式
- `conversations` / `messages`
- `tickets`：仅学员工单

检索硬约束始终不变：只在允许的 `space_id` 里取 Top-K，禁止先搜全集再过滤。

入库流水线（MVP 与 V1 相同内核）：选空间 → 解析 → 切片 → 向量 → 写入；失败则该文档不可检索。

## 9. 非功能需求

| 项 | MVP | V1 |
| --- | --- | --- |
| 时效 | 问答目标 15 秒内出结果或失败说明 | 同左；入库异步不阻塞问答 |

| 部署 | 本机能跑通 API + 数据库 | Docker Compose 整包 |

## 10. 验收标准

**MVP（课程实践当前关卡）**

- 手动入库的课程文档，学员身份能问到并带来源。
- 公司样例文档，学员身份问不到任何内部正文或标题。
- 员工 / 教学岗身份的检索范围符合第 4.1 节映射。
- 库中没有的问题被明确拒绝，不编造来源。

**V1（产品关卡，后做）**

- 真实登录；教学岗写入成员表后两空间可检。
- 学员未命中生成班主任工单；员工未命中展示负责人联系方式或「未配置」。
- 伪造公司 `space_id` 的学员 token 检不到公司切片。
- 对话不写入知识库。

## 11. 范围

**MVP（现在写代码的范围）：** 双空间入库 + 隔离向量检索 + LLM 带依据作答 + 未命中拒答 + 身份模拟演示。

**V1：** 登录、管理员上传后台、教学岗成员、班主任工单、员工负责人联系方式。

**V2：** 飞书/微信入口与导入、入职路径、带练、确认后入库、截图、代码检索、在线编辑、SSO。
