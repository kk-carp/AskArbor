# 混合检索与重排

> **补充参考（已落地）**：默认 hybrid + rerank；`rerank_min_score=0.5`（见 `backend/config.py`）。文档索引见 [README.md](./README.md)。评测见 [16-评测闭环对比.md](./16-评测闭环对比.md)。

空间隔离、ready-only、拒答语义不变。检索为 dense + 词法 → RRF → 重排 → 阈值。可用环境变量关掉 hybrid 或 rerank。

主路径：`qa_service._retrieve` → `run_retrieval`。进阶资料课内检索共用同一入口。

---

## 1. 流水线

```
question
  → retrieval_query_for_question（+ 可选岗位 boost）
  → dense：encode_query → search_dense(candidate_k)
  → lexical：jieba + tsvector → search_lexical(candidate_k)
  → RRF 融合 → rerank → retrieve_top_k
  → 阈值门控 → generate / miss
```

对外仍只暴露 `/ask`、`/ocr`；检索细节不出 API。不引入 ES、Celery、BGE-M3 sparse / ColBERT。客户端不能传 `space_ids`。

---

## 2. 技术选型

### 2.1 词法召回

| 项 | 选择 |
| --- | --- |
| 存储 | `chunks.content_tsv tsvector`（入库时写入） |
| 索引 | `GIN(content_tsv)` |
| 查询 | `plainto_tsquery('simple', :q)` + `ts_rank_cd` |
| 中文 | 入库与查询均 jieba 分词后再交给 `simple` 配置 |

不用 zhparser（镜像难统一），本路不做纯 pg_trgm。

### 2.2 融合：RRF

默认 `rrf_k=60`。融合分只用于排序，不与 `retrieve_min_score` / `rerank_min_score` 直接比。

### 2.3 重排

进程内 `BAAI/bge-reranker-v2-m3`（`CrossEncoder`），启动加载一次。融合后最多 `rerank_candidates`（默认 20）条送入，再取 `retrieve_top_k`（默认 5）。内存不够可改 `RERANK_MODEL=BAAI/bge-reranker-base` 或关 rerank。

不做 LangChain 编排、远程 Rerank HTTP、按文档类型拆索引。

---

## 3. 分数与拒答

- 开 rerank：门控用 `rerank_min_score`（默认 **0.5**），不用 `retrieve_min_score` 去比 rerank 分。
- 关 rerank：门控用 dense 余弦 `retrieve_min_score`（当前默认 **0.5**）。纯词法命中若无 dense 分，关 rerank 时 `score=0`。
- 候选空或最高分低于阈值 → 固定拒答、不调 DeepSeek。
- `RetrievedChunk.score` 对外写最终用于排序与门控的分数。

课内进阶资料工具与问答共用同一套门控。

---

## 4. 配置

| 配置 | 默认 | 含义 |
| --- | --- | --- |
| `retrieve_top_k` | `5` | 送给生成的条数 |
| `retrieve_min_score` | `0.5` | 关 rerank 时的 dense 门控 |
| `retrieve_use_hybrid` | `true` | 词法路 + RRF |
| `retrieve_use_rerank` | `true` | 重排 |
| `retrieve_candidate_k` | `20` | 每路召回条数 |
| `retrieve_rrf_k` | `60` | RRF 常数 |
| `rerank_model` | `BAAI/bge-reranker-v2-m3` | 重排模型 |
| `rerank_candidates` | `20` | 送入重排的上限 |
| `rerank_min_score` | `0.5` | 开 rerank 时的门控 |

对照：双关 = 纯 dense；只混合 = hybrid 开、rerank 关；默认双开。

---

## 5. Schema

```sql
ALTER TABLE chunks ADD COLUMN IF NOT EXISTS content_tsv tsvector;
CREATE INDEX IF NOT EXISTS ix_chunks_content_tsv ON chunks USING GIN (content_tsv);
```

新入库写 `content_tsv`；旧行在 `init_db` 对 `content_tsv IS NULL` 回填。`search_lexical` 与 `search_dense` 的 `WHERE` 必须含：

```sql
chunks.space_id = ANY(...)
AND documents.status = 'ready'
```
