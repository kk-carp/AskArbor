# V1 需求分析

| 项 | 内容 |
| --- | --- |
| 对应基线 | `docs/需求分析.md` 第 5–7、9–11 节；`docs/系统架构设计.md` 第 10.1 节；`docs/任务拆分.md` V1 表 |
| 前置条件 | MVP（T13）主链路可用：入库、隔离检索、命中来源、未命中拒答 |
| 范围 | 产品化能力（登录、成员授权、文档后台、会话、转人工、Compose 整包） |
| 不在范围 | OCR、沙箱、代码仓、Gradio、流式 SSE、独立前端、微服务拆分 |

本文说明 **V1 做什么、不做什么、如何验收**，并对照当前仓库给出差距。实施任务见 `docs/V1任务拆分.md`。

---

## 1. 背景与目标

### 1.1 结论

V1 目标是把「可演示的 RAG 内核」升级为「可登录、可授权、可运维文档、可转人工」的最小可上线产品，且 **不重写 RAG 主链路**。

### 1.2 相对 MVP 的增量

| 能力 | MVP | V1 |
| --- | --- | --- |
| 身份 | 请求参数 `role` 模拟（或演示账号） | 登录态；服务端按成员关系算允许空间 |
| 问答 | 未命中固定拒答 | 未命中分流：学员建工单 / 员工展示负责人 |
| 文档 | 上传入库 | 状态/失败原因可见；可下线且不可检索 |
| 会话 | 单次问答 | 同一会话追问（对话不入库） |
| 部署 | 本机 API + Compose 起 DB | Compose 整包 API + Postgres |

### 1.3 硬约束（继承 MVP，V1 不得破坏）

1. 单体 FastAPI + PostgreSQL/pgvector；不拆微服务。
2. 空间过滤必须在检索 SQL 的 `WHERE` 中；禁止全量检索后再用 Python 过滤。
3. 客户端不得决定 `space_ids`；允许空间只由服务端计算。
4. 未命中或低于阈值时不调用 DeepSeek；来源只来自召回记录。
5. 系统故障（502/503）与知识库未命中（200 + `hit=false`）语义必须区分。
6. 对话内容不得自动写入知识库。

## 2. 范围与非目标

### 2.1 V1 范围内

- 账号登录（无游客问答）。
- `users` + `space_members` 真实授权（替换对客户端 `role` 的信任）。
- 教学岗：同时拥有 `student` 与 `company` 成员关系。
- 文档管理最小后台：列表/状态/失败原因/下线（`offline`）。
- 会话：`conversations` / `messages`，支持追问。
- 学员未命中 → 班主任工单（`tickets`）。
- 员工未命中 → 主题负责人联系方式（`topic_owners`），未配置则明确说明。
- Docker Compose 一键启动 API + 数据库（仍为单体）。
- 最小审计日志：用户、角色、空间、是否命中、引用文档 ID。

### 2.2 V1 明确不做（留给 V2 或更后）

- 沙箱、OCR、代码仓解析、tree-sitter、作业批改、学习路径。
- Gradio 场景页、SSE 流式输出、独立 Next.js 前端。
- Redis、Celery、对象存储、Alembic（可选延后到表结构频繁变更时再引入）。
- 对话自动入库、SSO/飞书作唯一入口、两场景拆成两套后端。

### 2.3 待确认（不阻塞文档与排期，实现前需拍板）

- 班主任绑定是否需要「班级」实体，还是学员直接挂 `advisor_id` 即可。
- 内部主题分类第一批清单（用于 `topic_owners`）。
- 部署环境与演示账号规模。

## 3. 统一术语

| 术语 | 含义 |
| --- | --- |
| `allowed_spaces` | 当前登录用户可检索的空间 ID 列表，仅服务端计算 |
| `hit=false` | 知识库未命中或低于阈值；HTTP 200；不调 DeepSeek |
| `offline` | 文档主动下线状态；切片不得参与检索 |
| 班主任 | 绑定到学员的处理人；接收学员工单 |
| 主题负责人 | 内部问题分类对应的联系人；员工未命中时展示 |
| 教学岗 | `is_teaching=true` 的员工；成员表含 `student` + `company` |

角色与空间标识统一使用：`student`、`employee`、`teaching`（展示语义）、`company`。

---

## 4. 角色与权限模型

### 4.1 角色语义（V1）

| 身份 | 存储建议 | 可检索空间 | 未命中行为 |
| --- | --- | --- | --- |
| 学员 | `role=student`，`is_teaching=false` | `student` | 建班主任工单 |
| 内部员工 | `role=employee`，`is_teaching=false` | `company` | 展示负责人或「未配置」 |
| 教学岗 | `role=employee`，`is_teaching=true`（或等价标记） | `student` + `company` | 按提问意图分流；默认不建学员单除非明确走学员侧转人工 |

### 4.2 授权判定顺序（服务端）

1. 未登录 → 401，禁止 `/ask`。
2. 读 `space_members` 得到 `allowed_spaces`。
3. 无成员 → 空列表，问答走未命中（不调 DeepSeek）。
4. 检索 SQL：`chunks.space_id = ANY(:allowed_spaces)` 且 `documents.status = 'ready'`（下线后不含 `offline`/`failed`）。

### 4.3 禁止事项

- 客户端传 `role` / `space_ids` 改变检索范围。
- 学员会话返回 `company` 空间的标题、片段、来源或文档 ID。
- 用 Python 对全库召回结果做事后过滤冒充隔离。

## 5. 关键业务流程

### 5.1 登录与会话 Cookie

```text
POST /login(username, password)
  → bcrypt 校验
  → 写入签名 Session（user_id）
  → 返回 username / role / is_teaching / allowed_spaces

GET /me → 当前登录用户与允许空间
POST /logout → 清空 Session
```

### 5.2 问答授权链路（V1 目标）

```text
登录用户
  → load_auth_context
  → allowed_spaces（来自 space_members）
  → encode_query → search_chunks(WHERE space + ready)
  → 未命中？
        ├─ 是：按角色分流（工单 / 负责人），不调 DeepSeek
        └─ 否：generate_answer + 来源去重（最多 3 条）
```

可选：请求携带 `conversation_id`，加载同会话历史作为生成上下文；**消息不入库为文档**。

### 5.3 未命中分流

**学员**

1. 返回固定拒答文案，`hit=false`。
2. 自动或显式「转人工」创建 `tickets`。
3. 默认处理人 = 学员绑定的班主任（`advisor_id`）。
4. 班主任可在后台回复；回复不写入知识库。
5. 502/503 **不得**建工单。

**内部员工**

1. 返回固定拒答文案，`hit=false`。
2. **不默认建工单**。
3. 匹配负责人：主题表 →（可选）弱相关文档上的负责人 → 未配置则返回「未配置」。
4. 禁止模型编造姓名或联系方式。

### 5.4 文档状态管理

| 状态 | 含义 | 是否可检索 |
| --- | --- | --- |
| `processing` | 入库中 | 否 |
| `ready` | 成功 | 是 |
| `failed` | 失败，有 `error` | 否 |
| `offline`（V1 新增） | 主动下线 | 否 |

管理员可：上传、查看列表与失败原因、下线、（可选）换版本重新入库。

## 6. 数据与接口增量

### 6.1 表（相对 MVP）

| 表 | 用途 | V1 是否必须 |
| --- | --- | --- |
| `users` | 账号、角色、教学岗、班主任绑定 | 是 |
| `space_members` | 用户 ↔ 空间 | 是 |
| `conversations` / `messages` | 多轮追问 | 是 |
| `tickets` | 学员工单 | 是 |
| `topic_owners` | 主题 → 负责人联系方式 | 是 |
| `documents.status=offline` | 下线 | 是（字段扩展） |

### 6.2 接口增量（建议）

| 接口 | 说明 |
| --- | --- |
| 已有 `/login` `/logout` `/me` `/ask` `/documents` `/health` | 保持；`/ask` 继续登录态 |
| `GET /documents` | 列表：状态、失败原因 |
| `POST /documents/{id}/offline`（或 PATCH） | 下线 |
| `POST /ask` 增加可选 `conversation_id` | 会话追问 |
| `GET/POST /tickets` 及班主任回复 | 学员工单 |
| `GET/PUT /topic_owners` | 负责人配置（管理） |

具体路径可在任务拆分中微调，但语义不得偏离本节。

## 7. 错误语义与审计

| 场景 | HTTP | 业务语义 |
| --- | --- | --- |
| 未登录 | 401 | 禁止问答 |
| 参数错误 | 400 | 问题为空等 |
| 知识库未命中 | 200，`hit=false` | 可触发转人工分流 |
| DeepSeek 失败 | 502 | 不建工单、不伪装未命中 |
| DB/模型未加载 | 503 | 不建工单、不伪装未命中 |

审计最小字段：用户 ID、角色、`allowed_spaces`、是否命中、引用 `document_id` 列表、错误类型（未命中/502/503）。

## 8. 验收标准（产品关卡）

1. 未登录调用 `/ask` 返回 401。
2. 学员登录后伪造请求体中的 `role`/`space_ids`，仍检不到 `company`。
3. 教学岗成员表含两空间，课程与制度问题均可命中且来源空间正确。
4. 学员未命中生成班主任工单；502 不建单。
5. 员工未命中展示负责人或「未配置」，不编造联系方式。
6. `failed` / `offline` 文档不出现在检索结果。
7. 会话追问可用；对话内容不自动成为知识库文档。
8. 本机按 README/Compose 可启动 API + Postgres（单体）。

## 9. 现状差距分析（相对当前仓库）

对照时间点：结构已迁至 `routes` / `services` / `domain` / `infra` / `seed`；登录与成员授权主路径已落地。

| V1 能力 | 状态 | 说明 |
| --- | --- | --- |
| V1-T1 登录与用户 | **核心已完成，需收口** | Session 登录、`users`、演示种子、演示页登录；缺用户管理 API、上传仍免登录、`advisor_id` 未真正绑定 |
| V1-T2 空间成员授权 | **核心已完成，需收口** | `space_members` + `load_auth_context`；`/ask` 只信成员表；遗留 `roles_compat` 仅兼容/种子用途，问答路径不得再走 role 直映射 |
| V1-T3 文档后台 | **部分完成** | 有 `processing/ready/failed` 与入库；无 `offline`、无列表/下线管理、上传无管理员鉴权 |
| V1-T4 会话 | **已完成** | 会话追问 + GET 列表/消息；502/503 不落库 |
| V1-T5 学员工单 | **未开始** | 仅有 `advisor_id` 字段占位；未命中仍固定拒答 |
| V1-T6 内部负责人 | **未开始** | 无 `topic_owners` |
| V1-T7 Compose 整包 | **部分完成** | Compose 仅 Postgres；API 仍本机 uvicorn；无 Dockerfile |

### 9.1 风险

1. 文档上传未鉴权 → 任意访客可写库（V1 应收口为管理员）。
2. `advisor_id` 空 → 工单无法默认指派班主任。
3. 误把 502/未命中写进同一分支 → 违反错误语义。
4. Compose 未含 API 时易误判「已整包」。
5. 会话上下文若污染 Prompt，可能削弱「只依据片段」护栏，需单独验收。

### 9.2 建议落地顺序

1. 收口 T1/T2 缺口（班主任绑定、上传鉴权、清理对 `role` 的误导文档）。
2. T3 文档后台（`offline` + 列表 + 管理员权限）。
3. T5 / T6 未命中分流（与问答编排扩展点对接）。
4. T4 会话。
5. T7 Compose 整包与 README 对齐。
